# 搜不到,不等于没说过

> 我在复核另一个会话的设计时,对 Owner 说:
> 「这两句我在本机所有聊天记录里都没搜到,已请它给出处,给不出就注明是转述,不能当你的原话写进记录。」
> 那两句都是 Owner 自己说的。**错的是我的搜法。**

## 发生了什么

2026-09-18,管机器人代码的平级会话要实施「遇事才想」。
它引了 Owner 的两句原话来定机制(原话和时间见 [27](27-the-loudest-is-not-the-costliest.md))。
13:15 JST,我在复核里提了两条反对:

1. **这两句在本机所有会话记录里都搜不到。** 我请它给出处,给不出就标「转述」。
2. **平常的选择点别跟着改。** 活做完了、挑下一件时,如果也改成「只有同一档有好几件才问模型」,
   那就改了「候选多个就问模型、按性格挑」的规格。我说这得 Owner 拍板,这一刀请只改「出了事之后」。

**两条都在同一份汇报里告诉了 Owner。** 第 2 条我是这么说的:
「平常活干完、挑下一件时,还按原来的规矩让大脑按性格挑,不能顺手改掉。要改这条得你点头。」

**第 1 条错了;第 2 条站不住。** 是 Owner 让我把这一轮记到 GitHub,我在写记录时自己查出来的。
平级会话还没来得及回我出处,我就查到了。两条都已经分别向平级会话和 Owner 撤回。

那段时间里,Owner 从我这里听到的是两件事:另一个会话可能在错引他的话;它可能要改规矩,得他点头。
实际上两句都真是他说的,引的意思也对(第二句是缩写,省掉了「寻找本地模型进行」几个字)。
改的方向也和他自己的表一致。

## 第 1 条错在哪:三种搜法,一次对不上号的对照

| 我用的搜法 | 结果 | 为什么 |
|---|---|---|
| Python 逐行解析,只看类型是 `user` 的记录 | 0 条 | Owner 在会话**正忙时**打的字,记录类型是 `queue-operation`,不是 `user`。两句原话恰好都是这么打进来的 |
| `grep -rlF "…" --include=*.jsonl .` | 报 `no matches found`,grep 根本没运行 | zsh 先把没加引号的 `*.jsonl` 当通配符去展开,展开不出东西,整条命令就不执行了 |
| `grep -rhoE '.{0,100}(…).{0,100}' --include='*.jsonl' . 2>/dev/null` | 0 条 | 见下 |

第三种最阴险。事后我拿一句**已知存在**的原话,在本项目的会话记录目录下,只用其中一个词「继续上一个任务」,
只改前后窗口的大小,重新跑了四次。(它和当初那条不完全是同一条命令:当初搜的是所有项目、三个词一起搜。)

```
窗口 .{0,20}     169 行
窗口 .{0,40}     169 行
窗口 .{0,60}       0 行
窗口 .{0,100}      0 行      ← 换成 UTF-8 的 locale 也一样
```

**同一批文件、同一个词,窗口从 40 开到 60,就从 169 行变成了 0 行。**

事后查清了两件事:

- **这里的 `grep` 不是 Mac 自带的那个。** 在我跑命令的这个环境里,它是 Claude Code 在 shell 里包的一层 ugrep,
  默认带着 `-I`,意思是跳过它认为是二进制的内容。
  我的备忘里早就记着一条:这台机器上的 grep(ugrep)碰到坏掉的中文编码,会**直接什么都不输出**。
- **我当时加了 `2>/dev/null`,提前堵住了它可能说的话。** 所以它到底是悄悄返回空,还是报了错被我自己扔了,**当时分不出来**。

这两件只说明那个「0」不可信,**都没有解释为什么偏偏是 60** —— 这一点我没查清。
还有一处没对上:整批跑窗口 40 能出 169 行;单挑一个文件、留着错误输出重跑窗口 40 和 60,都在 100 秒内没跑完。

不管是哪一种,结论都一样:**这条命令给出的「0」,不能当「没有」用。**

**我其实做过阳性对照。** 用 `grep -rlF '暂时先别圈了' --include='*.jsonl'` 搜 Owner 的另一句话,搜到了。
但那条命令是**第四种写法**(通配符加了引号,又用 `-F`),而得出「搜不到」的是前三种。
**我拿来对照的搜法,不是我拿来下结论的搜法。**

> 换了写法的对照,只能证明「数据里有这句话」,证明不了「我下结论用的那条命令搜得到」。
> 给阴性结果做阳性对照,必须用**一模一样的命令**,只把要搜的词换成一句已知存在的话。

## 第 2 条错在哪:对方点了出处的名字,我没去找

我对照的是 [`server/11`](../server/11-ai-player-brain.md) 里的「候选多个就问模型」。那条是 2026-09-18 凌晨 00:38 写进去的。
同一天 11:42,Owner 发来一张目标分解表。大目标和小目标两栏「优先级」的表头写的是:
**「数字越低优先级越高,当优先级一致的时候由ai来选择先完成那些目标 或者同时进行」**。

这句话**直接就管平常的选择点**:不同档按数字先后,只有同一档才交给 AI 挑。不需要推论,也用不着再让 Owner 拍板。
我要 Owner 拍板的,正是他自己已经写在表头里的东西。

平级会话 13:08 发给我的设计里,点了出处的名字:它采纳的是另一个会话(fork 2)的意见,**「fork 2 是照 Owner 的四层表说的」**。
它没给文件在哪,但名字点到了。**我没去找那张表,拿手里那份旧的去对了。**
(「同一档有好几件才问模型」这个读法、以及第二句原话,最早都是 fork 2 提出来的,平级会话采纳了。)

(我的记忆索引里后来也出现了「2026-09-18 升级为四层+思考触发」这一行。那是另一个会话 12:59 写的,
13:21 才进到我这边,在我提反对之后。所以不能说「它一直在我眼前」。在我眼前的,是平级会话那句话。)

> 判断「符不符合 Owner 的规格」之前,先确认手上那份是最新一版。
> 对方已经说了他依据的是哪一份时,先去找到、打开那一份。
> 规格升级了,旧版不会自己作废。它就留在原处,看上去和新版一样权威。

## 同一份汇报里还有一处

我告诉 Owner:「上一次触发还是 16 号凌晨 1 点 20 分。」
这个时间是从机器人日志里抄的,**而机器人日志用的是 UTC**。换成 Owner 所在的日本时间,是 **16 号上午 10 点 20 分**。
这一处也已经在同一轮汇报里向 Owner 更正。

我自己在 [26](26-that-was-not-a-control-group.md) 里写过:
「两个来源的时间戳放在一起比之前,先把其中一个换算出来写在纸面上,再比。」
这次连「比」都没有,只是抄一个时间给 Owner。**抄的时候就该写上它是哪个时区。**

## 教训

**1. 「我没搜到」和「没有」之间,隔着一次阳性对照,而且对照要用同一条命令。**

**2. 过滤条件本身就是一个假设。**
「用户说的话 = 类型为 user 的记录」,在用户边等边打字时就不成立。
写过滤条件之前,先看一眼原始数据里到底有几种形态。

**3. 报错也要读懂是谁在报,而且别提前把它堵住。**
zsh 那句 `no matches found` 的意思是「通配符没匹配到文件,命令根本没跑」,字面上却像「没搜到」,我把它也算进了「搜不到」。
grep 那次,我用 `2>/dev/null` 提前堵住了它可能说的话,所以它交回来的「0 行」,我连「它有没有报错」都没法知道。
**还要知道自己手里的命令到底是哪个程序。** 同一个名字,换一个环境可能是另一个程序,默认行为也不一样。

**4. 质疑出处是对的,但措辞要跟着证据走。**
搜法本身没被验证之前,只能说「我没找到」。
这次错不在用了哪个词,在于**我带着「可能是转述」这个结论去找了 Owner**。

**5. 核别人之前,先核自己手上的规格是不是最新的。** 对方给了出处,先打开出处。

**6. 从日志里抄时间给 Owner 之前,先写下它是哪个时区。**

> **阴性结果要付出的检验,比阳性结果多一步:你得先证明,这个搜法本来能搜到。**
