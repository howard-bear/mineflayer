# 把日志接到公开网页上,搬走的不只是你想要的那一行

> 需求很小:让地图网页显示游戏里的聊天。
> 最自然的做法是 `tail` 日志、挑出聊天行。**而这台服务器的日志里,今天有 76 条明文密码。**

## 先看数据,再写解析器

这是一台离线服务器,孩子靠 nLogin 的密码登录 —— 也就是说每个人每次进游戏都要打一次
`/login 自己的密码`。而 Paper 会把玩家执行的命令记进 `latest.log`。

在写任何解析之前先数了一遍当天的日志(只统计命令名,一个参数都没打印):

```
286 /home       42 /login      ← 后面跟着密码
 56 /menu       34 /register   ← 后面跟着密码
 43 /give       40 /l          ← /login 的简写,一样
```

`/login` + `/l` + `/register` 合计 **76 条**。另有 65 行私聊。

**目的地是一个公开、无密码、任何人都能打开的网页。**
贴上去就收不回来了 —— 别人的浏览器、搜索引擎缓存、别人的截图,都不受你控制。

## 只能用白名单

日志里唯一算"公屏发言"的行长这样:

```
[22:02:35] [Async Chat Thread - #27/INFO]: [Not Secure] zodiac_bear: 你这个柱子真的神来之笔
```

所以判据写成**只有严格匹配这一种格式的行才通过**,其余一律丢弃:

```python
CHAT = re.compile(
    r"^\[(\d{2}:\d{2}:\d{2})\] \[Async Chat Thread - #\d+/INFO\]: "
    r"(?:\[Not Secure\] )?([A-Za-z0-9_]{1,16}): (.+)$"
)
```

> **不要写成"排除掉密码"。** 排除法要求你把所有危险格式都想全,
> 而你只要漏掉一种写法(比如 `/l` 这个简写),就是一次**不可逆**的事故。
> 白名单漏掉一种,代价只是"少显示几条聊天"。
> **两种错误的代价差了几个数量级,判据的方向就该跟着它走。**

沙箱里拿真实格式验过:密码行、私聊行、命令行全部被丢掉,只有聊天行通过。

## 两个 bug,都不报错,都长得像"没人说话"

功能写完之后在沙箱里跑了四种情况,抓到两个:

**① 日志轮转之后永久停更。**
这台服务器每天 05:00 自动重启,会换一个新的 `latest.log`。
我的代码发现文件换了就重新打开 —— 然后 `seek(END)`。
新文件是空的,"末尾"就是开头,但轮转瞬间写进去的那几行已经越过去了。
更要命的是之后也接不上。**表现:每天早上聊天窗静默死掉。**

**② 存满 60 条之后永久停更。**
我用"消息条数变了没有"来判断要不要写盘:

```python
before = len(msgs)
take(line)
if len(msgs) != before:   # ← 存满 KEEP 条之后,长度永远不变
    dirty = True
```

前 60 条一切正常,第 61 条开始网页再也不动。
改成让 `take()` 自己返回"收下了没有",不靠长度推断。

**这两个 bug 的共同点,比它们本身更值得记:**

> **它们都不抛错、不留日志,表现完全一样 —— 网页上不再出现新消息。**
> 而"不再出现新消息"和"现在真的没人说话",**在界面上是同一个画面。**

一个没有失败信号的失败。你不会发现它,只会觉得"最近大家不怎么聊天"。

所以界面上放了一个**「更新于 23:24:01」的时间戳**和一个连接状态点。
它不解决 bug,但它让 bug 有了样子:时间戳停在两小时前 ≠ 大家安静了两小时。

## 顺带:别人输入的东西要当成代码看

聊天内容是**玩家能完全控制的字符串**,而它要出现在一个网页上。
沙箱里专门喂了一条 `<script>alert(1)</script>`,确认渲染时走的是 `textContent` 而不是拼 HTML。
（在公开地图上被 XSS,等于把所有看地图的孩子的浏览器交出去。）

## 做法本身:一个字都不改 BlueMap

整件事没有碰 BlueMap 的任何文件:

```
提取器    systemd 服务,读日志 → 写 /var/lib/mc-chatweb/chat.json
网页注入  nginx sub_filter,只给首页那一个 HTML 插一行 <script>
```

这样 BlueMap 将来升级不会把改动冲掉,回滚也只是还原一个 nginx 配置 + 停一个服务。
**"改在别人会覆盖的地方"是一种会在三个月后咬人的技术债**,而它当时看起来更省事。

## 教训

**1. 输出目标是公开的,判据就只能是白名单。**
   白名单漏一条 = 少显示一句话;黑名单漏一条 = 密码上网。
   **按"错了会怎样"选方向,不是按"哪个好写"。**

**2. 写解析器之前,先把要解析的数据数一遍。**
   我原本准备直接 `tail | grep` 聊天。真去数了才发现同一个文件里躺着 76 条密码。
   十分钟的统计,挡住的是一次不可逆的事故。

**3. 🔴 没有失败信号的失败,要自己造一个信号。**
   这个功能坏掉的样子和"大家没说话"一模一样。
   所以把"最后更新时间"放到界面上 —— **让沉默的失败变得可见,是功能的一部分,不是装饰。**

**4. 在沙箱里把"没修时是错的"先复现出来。**
   轮转那个 bug 是测出来的,不是看出来的;而满额那个是看出来的,但我仍然先写了一条
   "喂 65 条"的用例证明修法有效。**没复现过的修复,和没修一样不可信。**

> **搬运数据的时候,先问"这条管道里还流着什么别的东西"。**

⚠️ **附:这篇里我没复核的**

- 生产环境里**还没有真人在上线后说过话**(部署时正好没人聊天),
  所以"新说一句立刻出现"这条路在**生产**上是未验证的 ——
  沙箱里验过四种情况(白名单 / 满额 / 轮转 / 截断)都通过,但沙箱不是现场。
- 日志格式来自 `Paper 1.21.4` + `EssentialsXChat 2.21.0` 当前的行为。
  **换插件或升级 Paper 都可能改聊天行的格式**,而白名单的失效方式是"什么都不显示",
  不是"显示错东西" —— 这个方向是安全的,但要知道它会这么坏。
- 没有评估基岩版(Geyser)玩家的聊天行格式是否一致。

版本:`Paper 1.21.4`、`BlueMap 5.16`、`nginx 1.26.3`(带 `http_sub_module`)、`EssentialsXChat 2.21.0`。
