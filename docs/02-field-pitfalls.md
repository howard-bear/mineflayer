# 实测踩过的坑

按"会不会再咬人"排序,不是按发现顺序。

## 一、mineflayer / 插件本身

### 1. `collectblock` 会新建一份自己的 `Movements`,顶掉你那份

`CollectBlock.js` 里它自己 `new Movements(bot)`,砍树时用的是那一份。
你精心配置的 `blocksToAvoid`、`allow1by1towers=false`、`maxDropDown`
**只作用于你自己那份,对砍树完全无效**。

实测代价:被浆果丛(`sweet_berry_bush`)扎死 4 次 —— 因为避让清单只喂了一份。

```js
// 三份都要配,一份都不能漏(还有第三份在 mineflayer-pvp 手上)
const cm = bot.collectBlock && bot.collectBlock.movements
if (cm) { cm.allow1by1towers = false; cm.scafoldingBlocks = []; /* 避让清单也要喂 */ }
```

🔴 **注意是"逐项修改它那份",不是"把你自己那份赋给它"。**
如果你像我们一样为了不挖穿别人的建筑把 `canDig` 设成了 `false`,
把那份交给 collectblock 会让**每一棵树都被静默跳过、零报错**。
完整的源码链和三份 Movements 的全貌见 [07](07-three-movements.md)。

### 2. ~~`bot.on('death')` 会对一次死亡重复触发~~ —— 🔴 **这一条整个是错的,已推翻**

这里原本写着:「40 分钟窗口对账,服务器权威死亡 6 次、机器人收到 14 次,
所以 death 事件在重复触发」,并据此加了「满血满饱食才算数」的过滤。

**那个"服务器权威"是 `grep logs/latest.log` 数出来的,而这个口径只抓到真实死亡的约 0%。**
用玩家统计文件重新对账:**统计 194 | 广播 194 | 过滤后记账 4**。

→ **death 事件根本没有重复触发。广播是准的(92%)。**
   坏的是那道过滤 —— 它扔掉了 **76%** 的真实死亡,而它的依据正是那个漏记的日志。

完整的更正、正确的量法、以及死亡闭环的真机制(`respawn-at-home: true`)见
**[10 · 死亡到底该怎么数](10-counting-deaths.md)** —— 那是这个项目里最贵的一课。

> 这条留着没删,是因为**它错的方式比它本身更值得看**:
> 一个错的度量口径不会让你少知道一点,它会让你推出方向相反的结论,然后据此改代码。

### 3. `mineflayer-pvp` 的 `physicTick` 警告是噪音,不是 bug

`PVP.js:51` 用的是 `physicTick`(少一个 s)。**我一开始把它当成"功能失效"报了出去,是错的。**
`mineflayer/lib/plugins/physics.js:85-86` 两个都发:

```js
bot.emit('physicsTick')
bot.emit('physicTick') // Deprecated, only exists to support old plugins.
```

所以 pvp 照常工作,只是每次注册时打一行警告。
**但别把它数进"崩溃重启"里** —— 详见 [09](09-plugins-and-ports.md),我就是这么数错过一次的。

### 4. 寻路的"自动搭桥/搭塔"会破坏别人的地

在有真人玩的服务器上,`allow1by1towers` 和 `scafoldingBlocks` 必须关掉。
但关掉之后机器人会**困在坑里出不来**(既不会挖也不会垫高)——
所以必须同时给它一条别的出路(我们用的是 EssentialsX 的 `/home` 传送)。

> **给了建议却不给手段,等于没给。**
> 在提示词里写"在地下就想办法回地面",而菜单里没有任何"回地面"的动作 ——
> 它只会在洞里绕圈。

## 二、JavaScript 层面

### 5. 静默的 `catch` 会藏住整晚的 bug

游泳自救整晚没生效。日志看着完全正常 —— 因为 **日志打在抛错之前**,
而真正的异常(一个变量的暂时性死区 TDZ)被一个完全静默的 `catch (e) {}` 吞掉了。

`node --check` **查不出 TDZ**,它是运行期的。
规矩:**永远不要写空的 catch**,至少打一条节流日志。

### 6. 连败计数没有时间衰减 = 自锁死结

某个动作连续失败 3 次 → 被冷却屏蔽 → 既进不了菜单、也不被硬规则夺权;
而要清零连败计数,又**需要成功执行一次这个动作**。死结。

修法:给连败计数加时间衰减(我们用 3 分钟)。
另外:**逃生类动作永远不能被冷却**(`explore`、`go_home`)——
把唯一的出路冷掉,是"只堵不疏"。

## 三、测量方法本身的坑(这一类最阴)

### 7. `cut -c` 截断中文 → `grep` 完全不输出

按字节切会切断多字节字符,产生非法 UTF-8,某些 `grep` 实现会 **一条都不输出**
(不是报错,是静默地给空结果)。两个等待循环因此各自空转了 4 小时 56 分和 3 小时 49 分。

```bash
# 坏
cut -c1-95
# 好
awk '{ if (length($0)>95) print substr($0,1,95) "…"; else print }'
```

**所有等待判据一律用 ASCII。**

### 8. 用字符串比大小筛时间窗

```bash
awk '$0 >= "2026-09-16 16:40"'   # ← 以字母开头的行永远大于它,全部漏进来
```
结果:一条无害的警告被数成了"122 次崩溃重启"。**筛时间窗要锚定日期格式,不要比字符串大小。**

### 9. 跨午夜的时间比较

日志里只有 `[HH:MM:SS]` 没有日期时,过了午夜字符串比较就废了。
用相对秒数 + 回绕:

```awk
d = nowsec - t; if (d < 0) d += 86400
```

### 10. 固定的临时文件名

`/tmp/xx.log` 已经存在且不可写 → 重定向失败 → 统计跑在了**昨天的数据**上,而且完全静默。
用 `mktemp`,并且让脚本 **自检第一行的日期**。

### 11. 两份日志的时区不一样

机器人自己的日志是 UTC,Minecraft 服务端的日志是本地时区(差 9 小时)。
对账时不换算,就会得出"两个互相矛盾的事实"。

## 四、方法论

### 12. 局部修复会在别处制造新病灶

修好弓箭手(自杀式冲锋 1174 → 0 次)之后,**总死亡率反而从 4.0 升到 5.6 次/小时**:
新加的"自己造装备"链条排在"吃饭"前面,而 `forced` 只有一个槽位 ——
于是它会连续 90 秒做木板,直到饿死。

**只看单项指标会骗自己。每次改动都要看总指标。**

### 13. "我觉得应该是这样" 大约一半是错的

这个项目里被数据证伪的判断包括:"陷入死亡循环""跑了两个进程"(**这个猜了两次、被证伪两次**)、
"材料被无声吞掉""附近零动物""4b 模型跟不住 schema""砍树失败是因为找不到树"、
"death 事件在重复触发"(见 [10](10-counting-deaths.md))、
"pvp 是砍树静默跳过的主犯"(真主犯是我们自己在每次 collect 后换回了 canDig=false 的配置)、
"机器人在自己悄悄退出"(那是部署)、"房子的墙材料变了"(是泥土长草)。

定下的做法:**先取证 → 再改 → 改完必须有能证明它生效的日志。静默的修复等于没修。**

### 14. 写下来不等于会用上

有个坑叫「`setGoal(null)` 写在了条件分支外面,于是无条件销毁了刚设好的逃命目标」。
它在机器人主文件的**第 2494 行有完整的注释记录**,包括为什么危险。

然后在**同一个函数**里,**第 ③ 步做对了、第 ⑤ 步又犯了一遍同一个错** ——
每 15 秒无条件销毁反射层刚设的逃命目标,而时间点恰好是怪在旁边那一秒。

> **同一个教训,在同一个文件里,隔了一千行就没能传导过去。**

所以"写进注释"不是终点。真正能防住的只有两种:
- **把判据抽成唯一的函数**(见 [01](01-inventory-full-blocks-everything.md) 和
  [17](17-guardrails-disarming-each-other.md) 里那几次)
- **让错误的写法根本不可能通过**(闸门、断言、类型)

纯靠"我记得那里有个坑"是靠不住的 —— **写注释的人和踩坑的人是同一个,也一样。**
