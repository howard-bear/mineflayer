# 不碰别人东西的护栏

这个机器人住在一个**有一群小孩在玩的服务器**上。
"不破坏别人的东西"不是加分项,是能不能继续跑下去的前提。

## 一、它会把别人的房子当树砍

**最早也最尴尬的一个问题。** 玩家用原木盖房子,墙就是 `oak_log`,
而机器人找树的逻辑是 `findBlocks({ matching: 原木 })` —— 于是它开始拆房子。

护栏(两条同时满足才砍):
1. **上面必须有树叶** —— 自然长的树才有
2. **周围 3 格内不能有人造方块** —— 木板、楼梯、台阶、栅栏、门、玻璃、羊毛、
   混凝土、砖、火把、工作台、箱子、熔炉、床…… 有一个就不砍

```js
const MANMADE_RE = /planks|stairs|slab|fence|_door|glass|wool|concrete|brick|torch|
                    crafting_table|chest|furnace|bed$|carpet|ladder|trapdoor|sign|.../
```

⚠️ **性能坑**:第一版把护栏塞进 `findBlock` 的 `useExtraInfo`,
等于对整片森林的每一根原木都跑上百次方块查询 —— 主线程卡死,
决策间隔飙到 **129 秒**(比 30 秒的动作封顶还长,连计时器都挤不进来)。

改法:**先廉价地取最近的 12 根,再由近及远最多验 12 次,代价封顶。**

## 二、它会往别人的箱子里倒东西

原来的 `store_items` 是 `findBlock(最近的箱子, 32 格)` —— **谁的都行**。
实测:它家在 A 点,用的箱子在 19 格外的 B 点,里面有 31 种物品 ——
那几乎肯定是某个小孩的储物箱,累计 107 块木头很可能全倒进了人家箱子里。

修法:**只认自己放下的那一个箱子**(坐标记在文件里)。
没有就如实说"我还没有自己的箱子",宁可存不了。

## 三、放方块的"总闸"

寻路库为了走路会自动搭桥、搭塔。在别人的地盘上这就是破坏。

```js
// 关掉库的自动搭建(两份 Movements 都要关)
moves.allow1by1towers = false
moves.scafoldingBlocks = []
```

但"关掉配置"不够 —— **配置会被库的新版本改掉,也会被别的插件覆盖**。
所以再加一道总闸:包装 `bot.placeBlock`,**只放行坐标完全匹配的那一次**。

```js
let placeAllowedAt = null      // Vec3,null = 一律禁止

// 真正要放的那一瞬间才开,无论成败立刻关
placeAllowedAt = base.position
try { await bot.placeBlock(base, new Vec3(0, 1, 0)) }
finally { placeAllowedAt = null }
```

### 🔴 但这道闸有个缺口,而它恰好是"能盖房子"的物理前提

总闸只比较 `refBlock.position` 的三个整数,**完全不看 `faceVector`**。
也就是说:贴顶面、贴侧面、贴底面 —— **只要基准方块的坐标对得上,一律放行**。

这本来是个疏漏,但它正好意味着"往上叠方块"是免费的。
在做盖房子功能之前,我们先用一个**零模型的物理探针**证明了这件事:

| 探针 | 结果 | 耗时 |
|---|---|---|
| ① 地面放一块(顶面基准) | ✅ | 80 ms |
| ② 叠在上面(顶面基准) | ✅ | 144 ms |
| ③ **贴侧面**(侧面基准) | ✅ | 96 ms |
| ④ 再叠一层(测手能伸多远) | ✅ | 100 ms |

**4/4 全过,距离 1.2~2.15 格,服务器一次都没拒绝**(反作弊没取消、领地插件没拦)。

探针靠一个标记文件 `PROBE_PLACE.on` 触发,不用重启,跑完自删。
这个做法值得单独记一句:

> **先花十分钟证明"手能动",再花几百行谈功能。**
> 三套盖房子的设计方案全都押注在"往上叠方块能成"这条推理上,
> 而在探针跑之前,**这个代码库里从来没有一块方块被放在脚面以上过**。

⚠️ 反过来说:如果你**不**想让机器人往上叠,光比较坐标是不够的,`faceVector` 也要校验。

> **为什么是坐标而不是布尔开关:**
> 有个"挡箭"的功能是 fire-and-forget 跑的(不等它,免得堵住逃跑),
> 它把总闸打开的那几百毫秒里,机器人正被寻路驱动着跑 ——
> 布尔开关在那一瞬间对 **任何** 放置请求都放行,等于总闸失效。

## 四、"离家太远就不准动土"

```js
const canBuildHere = homePos && p.distanceTo(homePos) <= BUILD_RADIUS   // 24 格
```

没安家 = 一块都不许放。安了家 = 只能在家周围 24 格内。
离家太远又想建 → 先传送回家。

## 五、领地保护:护栏认不出"这是谁的地"

前面那些护栏只认"像不像建筑",**认不出"是不是别人的领地"**。
长在别人领地里的真树,树叶和周围都合格,照样会被盯上。

服务器会拒绝,但机器人不知道为什么,于是 **7 秒里被拒 15 次,一块没挖到,
最后被骷髅射死**。

补法:监听服务器的拒绝消息(`You don't have <名字>'s permission to build here.`),
记下坐标,**那一带 3 分钟内一律绕开**。

## 六、一条更普遍的教训

> **别拿"没核实的原因"去打发模型。**

放置失败时,原来一律回一句 "我不被允许自己放方块,需要有人给我放一个"。
可实际原因常常是 "周围没地方放"。这句假话
**既骗了模型(它会一直等人来帮忙),也骗了主人(我据此让主人去给它放箱子)**。

现在由放置函数自己如实记录原因:
`周围放不下(8 个方向里只有 2 个像是能放的,都没成),多半站在水里或不平的地方`。
