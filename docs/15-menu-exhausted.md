# 不是模型不听话,是菜单见底了

> 我们花了很久去提高"动作转化率"—— 模型选的动作有多少真的做成了。
> 从 14% 拉到 73%,修了背包、修了寻路、修了定时器。
> 然后转化率又掉回 20~30%,而这次**什么都没坏**。

## 现象

- 每轮 140 次决策里,**40~50 次被菜单拒掉**(模型选了一个"现在做不到"的动作)
- 存箱增速掉到 0~11 块/小时
- 它在一个 111×116 格的范围里来回游荡

看起来像是模型退化了,或者又有什么东西坏了。

## 真相:它已经把能做的事全做完了

清点它的 15 个动作能达成的所有目标:

| 能做的事 | 状态 |
|---|---|
| 砍树、存木头 | **已存 1026 块**,而大目标只要 64 —— 超额 16 倍 |
| 盖房子 | **已盖好**(4×4、两格高、门朝南) |
| 做工作台 / 箱子 / 木剑 | 都做过了 |
| 做石剑 | 需要圆石 → **需要挖矿** → 没这个动作 |
| 做任何工具、装备 | 同上 |

**每一条剩下的路,都要先会挖矿。而它不会挖矿。**

最有说服力的证据是它的规划师自己写的理由:

```
新阶段目标:砍 1 块木头存进箱子
因为:已存 700 块,目标已完成,需确认存入     ← 它自己都说完成了
```

```
新阶段目标:砍 1 根木头存进箱子
因为:已存 64 块,需补木头                   ← 数字还记错了
```

**它在给自己编凑数的活干。**

## 这改变了问题的定义

原来的问题是:*"怎么让模型少选做不到的动作?"*
—— 于是你会去改提示词、加约束、调菜单门槛。

真正的问题是:*"它还有什么事可做?"*
—— 答案是**没有了**。

> **转化率低不一定是执行层的问题。它可能是在告诉你:菜单见底了。**

而且这两种情况在指标上长得一模一样:决策多、成功少、来回游荡。
区分它们的办法只有一个 —— **去看它被拒掉的是什么动作,以及那些动作为什么做不到。**

我们这里是:`gather_wood` 被拒 27 次(周围没树,因为**家附近的树被它自己砍光了**)、
`store_items` 被拒 21 次(身上没东西可存)。两个都不是"模型选错了",
而是"这件事现在客观上没得做"。

## 三条

1. **目标完成了,要有人告诉它。**
   我们的大目标写死在配置里(`存 64 块木头`),而进度是 `storedTotal >= 64` ——
   **好几个小时前就恒为 true**,而没有任何机制据此换一个新目标。
   于是每轮处境都写着"目标已完成:是",菜单却还在端"砍树"。
2. **一个自主的 agent 需要"下一个目标"的来源。**
   要么人给,要么它自己能生成,要么有一棵目标树(比如游戏里的成就链)。
   三样都没有的话,它做完第一个目标之后就只会空转 —— **而空转看起来很像失灵。**
3. **它把资源用光了这件事,也要能被看见。**
   它砍光了家附近的树,背包里躺着几十个树苗,**而动作清单里没有"种"**。
   一个只会消耗、不会再生的 agent,产出必然随时间归零。

## 附:比"不会再生"更难看的一种 —— 再生的产出被自己扔了

后来发现死亡最便宜的解法是**一张床**(睡一觉跳过整夜)。
床 = 3 羊毛 + 3 木板。它木板有 9 个,而羊毛 —— 打羊就有,它一直在打羊。

但羊毛一直没攒起来,因为 `JUNK_RE`(背包满时自动丢弃的清单)里写着 `white_wool`:

```
🧹 背包满了(0 空格)—— 扔掉 10 样没用的杂物(arrow×5、white_wool×3、feather×4、…)
                                              ^^^^^^^^^^^^^ 正好一张床的量
```

**这份清单是为了治"背包满导致砍不动树"写的。在那个目标下,羊毛确实是杂物。**
目标变成"做一张床"之后,同一份清单就在**持续销毁瓶颈资源** ——
而它不会报错,也不会提醒你。

> **垃圾清单是随目标变的。** 目标一变,"什么算垃圾"就变了,
> 而清单不会自己跟着变。
>
> 更一般地:**任何"自动丢弃/自动清理"的规则,都隐含着一份当时的目标假设。**
> 那份假设失效的时候,规则不会失败 —— 它会继续正确地执行一件已经错了的事。
