# 接本地小模型的坑

用云端大模型驱动 mineflayer 是一回事,用一台家里的机器跑 **qwen3:8b / 4b** 是另一回事。
这一篇全是后者的实测。

## 一、`qwen3` 系列必须显式传 `think: false`

**不传的话,回复是空的。** 思考内容会把 `num_predict` 的预算吃光,`content` 剩 0 个字符。

同一个 `qwen3:8b`,各测 3 次:

| 请求 | 结果 |
|---|---|
| 传 `think: false` | ✅ 3/3 干净,385~431 ms,`content` 36 字,动作合法 |
| **不传 `think`** | ❌ 3/3 全空,`thinking` 348~351 字、`content` **0 字**、`eval_count` 200(预算全烧在思考上) |

而且 **这件事和 Ollama 版本有关**:

| | Ollama 0.32.5 | Ollama 0.33 / 0.34 |
|---|---|---|
| `qwen3:8b` 不传 `think` | 干净 | ❌ 返回空 |
| `qwen3:8b` 传 `think: false` | 干净 | ✅ 干净 |
| `qwen3:4b`(普通版)传 `think: false` | — | ❌ 推理塞进正文("首先,用户要求的是…") |
| `qwen3:4b-instruct-2507` | — | ✅ 干净 |
| `qwen2.5:*` 传 `think: false` | ✅ | ✅ 被忽略,**传了无害** |

**结论:对所有模型统一传 `think: false`** —— `qwen2.5` 会忽略它,`qwen3` 靠它活命。

> 这条事实的归因我错过两次:先归因成"某个操作系统上的 Ollama 组合问题",
> 后来被人纠正成"是模型本身、与版本无关"、我跟着抄进了代码注释,
> 结果升级 Ollama 之后实测发现 **版本确实有影响**。
> **教训:别人给的归因也要等他们的对照实验做全了再抄。**

## 二、8GB 的机器上放 8b 模型:不是慢,是根本留不住

实测 `qwen3:8b` 在一台 8GB 共享内存的机器上:
生成速度 11.4 字/秒(有独显的机器上是 47),加载后只剩 **86MB** 可用内存,靠 2.9GB 硬盘换页。

**更糟的是调用完 `/api/ps` 显示【空】—— 即使传了 `keep_alive: 30m`。**
等于每次调用都要从磁盘重新加载整个模型。
一个接在这上面的对话 NPC 因此 **每次要等 30 秒、而且返回空**。

对照:`qwen3:4b-instruct` 在同样的机器上 **模型稳定驻留 3.2G,连续 20 次调用零退化**。

## 三、4b 能扛结构化任务(这条可能出乎意料)

机器人的大脑要求模型从固定菜单挑一个动作、输出严格 JSON,系统提示 **3971 字**。
拿这个真实提示各测 5 次:

| 后端 | 平均耗时 | 动作合法 | 选的动作 |
|---|---|---|---|
| `qwen3:8b`(有独显) | 904~1529 ms | 5/5 | hunt |
| `qwen3:4b-instruct`(8GB Mac) | 845~3559 ms | **5/5** | hunt |
| `qwen2.5:3b` | 2156 ms | 5/5 | hunt |
| 普通 `qwen3:4b` | 54908 ms | **0/5** | 把处境原样吐了回来 |

**4b-instruct 和 8b 选了同一个动作,5/5 合法。**
⚠️ 但这只是 **一个情境 × 5 次**,撑不起"4b 媲美 8b"这种一般性结论。

## 四、🔑 最耐久的一条:结构化数据必须原样透传,不能让模型复述

同一道配方题:
- 不给资料时,3B / 7B / 14B **全错**(而且答得很笃定)
- 给了资料让它复述,约 11 次里 8 次对(**≈73%**)
- 要求 **原样输出** 那段资料,**100% 正确**

独立观察到同一现象:线上问"这个服务器有哪些职业"连问 3 次,**只有 1 次列全**。

→ **换更大的模型解决不了这个问题。**
凡是有标准答案的东西(配方、规则、清单),命中就 **逐字吐出**,别让模型转述。

## 五、菜单设计:能力弱的模型要靠结构约束,不能靠叮嘱

实测三次验证:在提示词里写 "你必须先 A 才能 B",小模型 **不会照做**。
有效的只有两招:

1. **做不到的动作根本不出现在菜单里**
   ```js
   if (woodNearby) avail.push('gather_wood')          // 附近没树就不给这个选项
   if (homePos && dist(p, homePos) > 24) avail.push('go_home')
   ```
2. **硬规则直接夺权**(不问大脑)
   ```js
   if (!forced && homePos && !myChest && woodCount() >= 4) forced = { action: 'build_base' }
   ```

⚠️ 但硬规则通常只有 **一个槽位**,所以 **顺序就是优先级**。
我们把"造装备"排在"吃饭"前面,结果它连续 90 秒做木板直到饿死。
**加一条硬规则时,一定要想清楚它会抢掉谁。**

## 六、别把本地模型打满

决策间隔的下限(`BRAIN_FLOOR_MS`)从 300ms 提到 2500ms 之后:
同一台机器上另一个 AI 的回话延迟从 **10156 ms 降到 3384 ms**,
而机器人自己的决策次数 **反而从 23 升到 45**(因为不再互相排队)。

**慢一点反而快。**
