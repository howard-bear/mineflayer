# "家" 有两份 —— 服务端权威状态 vs 机器人自己记的

一个很小的功能,暴露了一类很常见的 bug:
**同一个概念在两个地方各存了一份,而它们会悄悄对不上。**

## 背景

服主想把机器人的"家"设在自己站的位置。服务器上用的是 EssentialsX,
他在游戏里打一条命令就行:

```
/sethome <机器人名>:base
```

（`<玩家>:<家名>` 是 EssentialsX 给有 `essentials.sethome.others` 权限的人用的写法,
位置取 **发命令的人当前站的地方**。）

命令成功了。但机器人 **完全不知道**。

## 两份"家"

| 哪一份 | 存在哪 | 管什么 |
|---|---|---|
| **服务端权威** | Essentials 的玩家存档 | `/home base` 传送到哪儿 |
| 机器人自己记的 | 自己的 `home.json` → 内存里的 `homePos` | 能在哪动土、什么时候该回家、离家算不算远 |

**机器人读不到服务端那一份**:插件的数据目录属主是服务端进程的用户,
权限 `drwx--x---`,而机器人跑在另一个用户下 —— 实测 `Permission denied`。
这条路封死了。

## 对不上的时候会发生什么

不只是"数据不一致"这么温和 —— 它会 **卡死**:

`actGoHome` 的逻辑是:发 `/home base` → 等 4 秒 → 看自己到没到家。
家被挪走之后,它 **确实传送了**,但落点离它记的旧家还有几百格,
于是判定 `失败:动了 X 格但没到家` → 连败计数上涨 → **`go_home` 被冷却屏蔽** →
越挪越回不了家。

## 修法:靠落点反推

既然读不到,就从行为反推:**`/home base` 传送完它站在哪儿,那儿就是真正的家。**

判据必须 **两条同时成立**,否则会把"传送没成功"错当成"家挪了":

```js
function adoptHomeIfMoved (before, label) {
  if (!homePos || !before) return false
  const now = bot.entity.position
  if (now.distanceTo(before)  <= 16) return false   // ① 没挪窝 → 传送根本没发生
  if (now.distanceTo(homePos) <= 16) return false   // ② 落在旧家 → 家没动
  homePos = now.clone(); homeByOwner = true; saveHome()
  log(`家被挪了:以服务器为准,已改过来并落盘`)
  return true
}
```

- 只满足 ①:正常回家,不用改
- 只满足 ②:命令没生效(冷却/被打断),**它原地没动 —— 这时候绝不能把当前位置当成家**

挂钩点设在 **发送命令的唯一出口**(我们那个 `say()` 函数)上,
全文 8 处 `say('/home base')` 一次覆盖,将来新加一处也不会漏。

## 连带的死锁:挪家会把箱子锁死

家挪走之后,箱子还记在旧家、489 格之外。于是:

1. `bot.blockAt()` 够不到那个箱子(区块没加载)→ `store_items` **不进菜单**(这一步是对的)
2. 但 **清掉"我的箱子"的代码只在 `store_items` 的执行器里**,而执行器永远轮不到
3. 所以"我有箱子"永远为真 → "有木头、没箱子就回家建"那条硬规则 **永远不触发**

结果:它背着 27 块木头,既存不进去、也不会造新的,只能一直逛。

```js
// ⚠️ 判据用【记下来的坐标】,不能用 blockAt ——
//    blockAt 返回 null 只说明"区块没加载",不等于"箱子没了";
//    拿它当判据会让机器人一走远就把好箱子忘掉。
function forgetChestIfFarFromHome (reason) {
  if (!myChest || !homePos) return false
  const d = Math.hypot(myChest.x - homePos.x, myChest.z - homePos.z)
  if (d <= BUILD_RADIUS) return false
  log(`旧箱子离新家 ${Math.round(d)} 格 —— 不再当成"家里的箱子",回家重新造一个`)
  myChest = null
  return true
}
```

调用点:① 认了新家之后 ② **启动时对账**(两份状态在重启后最容易对不上)。

## 一条附带的设计教训

`loadHome()` 原本有一条校验:"家的高度低于海平面就作废,重新找" ——
那是用来 **否决机器人自己挑的烂地方** 的。

结果服主选的位置正好是 `y=63`,**会被当场作废**。

修法:存档里多存一个 `byOwner: true`,**主人定的家跳过这条校验**。

> **我给机器人定的标准,不该用来否决人给它下的命令。**
