# AI 玩家的脑子是怎么运转的(职业 + 脚本)

> 这一篇讲**架构**,`CHANGELOG.md` 里那条讲**为什么这么改、以及每一条的实测依据**。
> 想知道"它为什么做/不做某件事",看这篇;想知道"这个决定是怎么来的",看 CHANGELOG。

麦家现在有三个 AI 玩家,**跑的是同一份代码**,靠 `ROLE` 区分身份:

| 职业 | 登录名 | 中文名 | 会几个动作 | 数据目录 |
|---|---|---|---|---|
| `son` 丈夫 | XiaoMai | 小麦 | 19 | `~/mcbot/`(根目录) |
| `wife` 妻子 | MaiNiang | 麦娘 | 15(含 6 个种地动作) | `~/mcbot/data/wife/` |
| `child` 儿子 | MaiDou | 麦豆 | 6 | `~/mcbot/data/child/`(2026-09-18 上线) |

> **为什么不复制成三份代码**:那几条护栏(不砍别人用原木盖的房子、只在家附近放方块、
> 放方块总闸、不碰别人的箱子)是踩坑换来的。复制成三份就会分三份地腐烂,
> 修一次要改三处,漏一处就是在**有孩子的服**上出事。

## 一、四层结构

```
① 反射层    每秒一次。掉血/落水/岩浆/窒息 → 当场处理,不问模型,也不经过下面三层。
② 紧急硬规则 快饿死了就吃、手无寸铁就做剑、天黑就睡、离家 >100 格就传送回家……
             抢占当前动作,但【不动脚本的进度指针】—— 所以处理完自然接回原处。
③ 脚本层    大目标 → 小目标(脚本)→ 步骤(动作)。这一层是主力,见下。
④ 单步兜底  上面一个脚本都开不了工时,退回"让模型直接挑一个动作"的老路。
             宁可退化,绝不站着不动。
```

## 二、脚本层:模型只在"出现选择"时介入

```
大目标(每个职业好几个,带优先级)
  └── 小目标 = 脚本
        ├── 开工条件(任一成立)      ← 代码判据
        ├── 还要满足(全部成立)      ← 代码判据,安全门槛放这儿
        ├── 完成条件(全部成立)      ← 代码判据,【这个才是"做完了"的标准】
        └── 步骤[](可带「跳过条件」)
```

**一轮的流程**:

1. 手上有活 → 先用**代码**算 `完成条件`。成立就达成、清掉、进选择点。
2. 没达成 → 取当前步骤;`跳过条件`成立的步骤直接跳过(例:树就在眼前,不用先走去林子)。
3. 步骤走完但完成条件还没成立 → **从第 1 步再来一轮**(最多 6 轮)。
   governing 的是"完成条件",不是"步骤走完了" —— 砍树脚本只有两步,但要攒到 8 块木头。
4. 同一步连着失败 3 次 / 整件活超时 → 放下,**记进履历、进冷却**。
5. 选择点:候选由**代码**算出来(职业 + 动作表 + 开工条件 + 未完成 + 不在冷却)。
   - 候选 **0 个** → 退回单步兜底
   - 候选 **1 个** → 按优先级直接开工,**一次模型调用都不花**(没有选择就不该惊动模型)
   - 候选 **多个** → 这才问模型挑一个

**模型只做一件它擅长的事:在几个有名字的选项里挑一个。**
它不可能挑出做不到的事,因为做不到的根本不在名单上。

## 三、选择点喂给模型的东西

```
我的大目标          （好几个,带先后）
候选小目标          （代码算出来的,都确认过前提满足)
做过的小目标按顺序   ← 最关键的一条,见下
最近栽过还在冷却
家里的箱子里有什么   ← 存东西时顺手记的摘要
家里人              （谁在线、谁被授权进地盘）
身上有什么 / 血 / 饱食 / 离家多远 / 地图上记得什么 / 最近反复失败的事
```

**「做过的小目标按顺序」为什么最关键**:不给它,就会出现这种死循环 ——
放下一件刚失败的活,7 秒后又把同一件挑回来,每 13 秒一轮直到天亮。
因为模型每次看到的都是一张全新的候选名单,**没有任何东西记得它刚在这件事上栽过**。
履历存在 `history.json`(每个角色自己一份,存盘,重启不丢)。

## 四、三条不许违反的设计约束

1. **「做完没做完」必须是代码判据。**
   实测过让模型判断:它一边说「目标已完成」一边回答「继续」,白烧 364 秒。
2. **「能不能开工」必须是代码判据。**
   实测过不查前提:连着 3 次派"去林子"给一个地图里没有林子的角色。
3. **模型只挑脚本,不拼动作序列。**
   实测过让模型拼:每一份计划都有 1~2 步因为"不是它的活"或"它不记得那个地方"被丢掉。

> 这三条是同一个道理的三个面:**凡是能用代码确定的事,就不要问模型。**
> 模型的价值在"在几个都合法的选项里挑一个",不在"判断一个事实"。

## 五、私有的和共有的

| 私有(每个角色一份,在自己的数据目录) | 共有(`~/mcbot/family.json`,全家一份) |
|---|---|
| `home.json` 自己的家 | 家里那口箱子在哪、谁造的 |
| `house.json` 自己的房子进度 | 箱子里有什么(摘要 + 空几格 + 谁什么时候看到的) |
| `land.json` 自己圈的地 | 地盘圈在哪、谁圈的、授权给了谁 |
| `memory.json` 经验(FIFO 500 条) | 房子在哪、谁盖的 |
| `places.json` 走过的地方 | |
| `history.json` 小目标履历 | |

`MCBOT_DATA` 这个环境变量决定私有目录。**小麦不设它**,所以仍然是 `~/mcbot/` ——
它现有的存档一个都不用迁移。麦娘和麦豆各设一个子目录。
共有那份**故意**用代码所在目录,不跟着 `MCBOT_DATA` 走。

> 不隔开的后果是具体的:第二个进程起来第一件事就是把小麦的 `house.json` 和 `land.json`
> 覆盖掉 —— 而那两样刚花了一整天做成、服务器侧逐格复核过。

## 六、后台可视化管理

| 层 | 内容 | 谁能改 |
|---|---|---|
| **代码** | 判据(34 个)、动作、引擎 | 只能改代码 |
| **数据** `scripts.json` | 大目标表 + 脚本表(名字/职业/开工条件/还要满足/完成条件/步骤/优先级/开关) | **后台网页,热加载** |
| **数据** `roles.json` | 登录名/中文名/关系/人格/动作白名单/大目标 | 人格是热加载的,其余重启生效 |

后台能做的事:开关某个脚本、调优先级、把脚本分给别的职业、改大目标文字、
用判据菜单拼一个新脚本。**加新判据**才需要改代码。

> `roles.json` 是**执行闸,不是菜单**:动作不写进去,整套逻辑就是死码。
> 这一条栽过两次(加 `sleep` 那次、加 `claim_land` 那次),所以每次加新动作都要同步改它。

## 七、开关和回滚

| 想做什么 | 怎么做 |
|---|---|
| 整层关掉脚本层,退回旧的单步决策 | `/etc/mcbot.env` 加 `TASK_MODE=0`,重启 |
| 改"多久问一次"和"一件活最多干多久" | `TASK_REVIEW_MS` / `TASK_MAX_MS` |
| 停掉某个脚本 | `scripts.json` 里那条改 `"开": false`(热加载,不用重启) |
| 换回上一版代码 | `EXPECT_MD5=<当前md5> bash ~/deploy_safe.sh`,备份在 `~/mcbot/*.bak-*` |
