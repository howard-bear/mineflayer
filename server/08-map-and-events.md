# 地图、城堡对战和其它玩意儿

> 这篇是"剩下的东西":一个**网页地图**、一套**城堡对战**玩法,和几个不好归类的插件。
>
> 分量不均 —— 地图那节料最足(有配置原文),城堡那节料最少(**只有 6 个文件名和一行日志**)。
> 我按料多少写,没有硬凑。
>
> 全篇最值得记住的一条在 §一之二:**TPS 显示 20.0,玩家照样卡在「加载地形中」。**
> 那次事故的凶手不在游戏逻辑里,在**画地图的线程**里。

## 一、BlueMap:网页上的整个世界

玩家只需要知道一个网址:

| 是什么 | 值 | 出处 |
|---|---|---|
| 网页地图 | **map.v2good.com** | AI 村民老麦的 `quick-answers` 原文、`facts` 原文(两处都有) |
| 能看到什么 | 整个世界的地形 + **谁现在在哪儿** | 老麦原文:「就能看整个世界的地图,还能看到大家现在在哪儿」 |
| 要不要登录 | **不要**,浏览器直接开 —— 但这条**没有配置层面的证据**,见 §一之四 | [`06-platforms-and-login.md`](06-platforms-and-login.md) 的入口表同样记的是「所有人(浏览器)」 |

服务器上抓到的配置原文(`/opt/minecraft/plugins/BlueMap/core.conf`):

```conf
# By changing the setting (accept-download) below to TRUE you are indicating that
# you have accepted Mojang's EULA (https://account.mojang.com/documents/minecraft_eula)
accept-download: true
render-thread-count: 2
```

还抓到两个数:

| 项 | 值 | 我从它读出什么 |
|---|---|---|
| `enabled` | `true` | 插件在跑 |
| 地图配置文件数 | **55** | 数量级和「52 个世界全上图」对得上(3 + 49 = 52,见 [`05`](05-worlds-and-travel.md)) |

**关于 `accept-download: true`**:BlueMap 要画出方块的贴图,得先去下载 Mojang 的客户端资源,
这个开关等于声明"我接受 EULA"。不打开它,地图能出地形但没材质。
(这段是**我的理解**,素材里只有上面那句英文注释本身。)

**关于 55 这个数**,素材里只有孤零零一个数字,**没看到它到底数的是哪些文件**。两种可能:

1. 数的是整个 `BlueMap/` 目录下的 `.conf` —— 那 55 ≈ 52 份地图 + 3 份非地图配置(核心/网页/web 服务器),对得上;
2. 数的是 `maps/` 目录 —— 那就意味着**有 3 份地图配置对应的世界已经不存在了**。

第 2 种要当心:孤儿地图配置会让 BlueMap 每次启动都去渲染一个没有的世界。
**素材不足以区分这两种,所以这条只算"数量级对得上",不算核实。**

⚠️ 还有更糟的一点:**两份抓取自己就不一致。** 另一份素材里 BlueMap 那一节的"地图数"位置
只有一个孤零零的 `0`。`55` 和 `0` 里至少有一个不是地图数,而我分不出是哪个。
**所以这个数字现在只能当"待查",不能引用。**

> 顺带一条边界:素材里能看到 BlueMap 自带 web 服务器的**监听端口**,那是个内网端口号,
> 属于不进公开仓库的清单,这里不写。
> 至于孩子用的 `map.v2good.com` 和那个端口之间是怎么接上的(反向代理?端口映射?),
> **素材里没有任何证据**,我不猜。

### 一之二 · 🔴 `render-thread-count` 必须 = 2

这是本篇唯一一条**花钱买来的**教训。

⚠️ **先把出处说清楚,再看表:** 素材(服务器配置原文)里能证明的**只有"当前值 = 2"**这一件事。
下面这张表里其余每一格(`6`、`11 / 16 核`、TPS `20.0`)都来自仓库 [`CHANGELOG.md`](CHANGELOG.md) 里
那张**自己标着「日期未逐条复核」**的旧表,**没有当场复现过**。
现象我信(它是一次真事故留下的记录),但这些数字别当测量结果引用。

| | 改前 | 改后(出事的那次) |
|---|---|---|
| `render-thread-count` | **2** | 6 |
| 实际吃掉的 CPU | —— | **11 / 16 核** |
| 玩家看到什么 | 正常 | 卡在「**加载地形中**」进不去 |
| 服务器自己报的 TPS | 20.0 | **仍然 20.0** |

**为什么 TPS 会骗人:**

```
TPS 量的是      主线程每 50ms 跑完一轮没有
BlueMap 渲染在  独立线程,不占主线程的 tick
玩家卡在「加载地形中」= chunk 没发过来
                 ↑ 这件事不由 tick 快慢决定,由还有没有空闲 CPU 决定
```

也就是说:**渲染线程把核抢光的时候,主线程依然从容地 20.0,而玩家一个区块都收不到。**
监控面板全绿,玩家全都进不来 —— 这两件事可以同时为真。

**改的时候注意:**

- 这台机器 16 核,`2` 是个**留了大量余量**的值。想让地图渲染快一点的正确做法是**等**,不是加线程。
- 新增世界会增加渲染总量(49 个资源世界都在图上),但**加世界不等于要加线程** —— 渲染是可以慢慢排队的,玩家进不来不能排队。
- 调完这个值,**不要看 TPS 判断有没有事**。要看玩家端:能不能进服、进服要多久、区块出得快不快。
- 素材里有证据的只有**当前值 `2`**。「调到 6 会吃 11/16 核」这一条来自助手笔记,
  仓库的 [`CHANGELOG.md`](CHANGELOG.md) 里也有同一条记录,但那张表自己标注了「日期未逐条复核」。
  **现象我信,数字没当场复现过。**

> **TPS 正常 ≠ 玩家不卡。**
> 一个指标只要不量玩家实际等的那件事,它就有资格在事故中全程保持绿色。
> 这和 [`../docs/13-magic-numbers.md`](../docs/13-magic-numbers.md) 是同一类病:
> 一个拍出来的常数(6),不报错,只是安静地让别的事情不发生。

| 玩法书(`/opt/minecraft/plugins/Essentials/book.txt`,中英日三语) | **没有** —— 只有服务器地址、命令、圈地、摆摊、跨世界 | `book.txt` 全文 |

> 这不是 bug,是产品缺口:菜单还有空格子,加一格「地图」的成本接近于零。

## 二、城堡对战

**这是本篇料最少的一节。** 素材里关于城堡只有两样东西:6 个文件名,和一行日志。
下面严格分开写"文件名里读得出来的"和"读不出来的"。

### 二之一 · 6 个文件名

```
castle1_build.txt
castle1_mobs.txt
castle1_mobs.txt.bak-hp1784729341
castle2_build.txt
castle2_mobs.txt
castle2_mobs.txt.bak-hp1784729341
```

| 观察 | 读出什么 | 强度 |
|---|---|---|
| 编号 `1` / `2` | **两座**城堡,而且两边是对称配置(文件名成对出现) | 比较硬 |
| `build` 和 `mobs` **分两份** | 建筑方块和刷怪是**两套独立清单** —— 可以只重建建筑不重刷怪,反之亦然 | 比较硬 |
| 两份 `.bak-hp…` **只备份了 mobs** | 那次改动只动了怪,没动建筑 | 比较硬 |
| 后缀 `hp` | 改的是怪物**血量**一类的属性 | **猜的** |
| `1784729341` 当 Unix 时间戳解 | **2026-07-22 23:09 JST** | 合理但**是推算** |
| `.txt` 而不是 `.yml`/schematic | 重建是**自己写的脚本**在读纯文本清单,不是某个成品插件 | 中等 |

### 二之二 · 一键重建:一行日志

```
ok 重建完成(all) 08-31 01:53:42 耗时54秒
```

这一行能读出四件事:

| 字段 | 读出什么 |
|---|---|
| `ok` | 有状态码 —— 也就是**存在失败分支**,不是"跑完就算完" |
| `(all)` | 参数化过:`all` 之外应该能只重建其中一座 |
| `耗时54秒` | **全量重建 54 秒**。孩子还在线就能再开一局 |
| `08-31 01:53` | 上一次全量重建的时间(年份没打印,**推测 2026**) |

**为什么"一键重建"是这套玩法的命门:**

城堡对战的产物是**废墟**。打完一局,两座城堡都是坑。
没有重建脚本,这套玩法**一辈子只能玩一次** —— 或者每次都要管理员手动垒半天。
54 秒把"再来一局"变成了一个可重复的动作,这是整套玩法能存在的前提。

> **任何会被玩家破坏的玩法,真正的功能不是"造出来",是"能一键造回来"。**
> 城堡本身是内容,重建脚本才是产品。

### 二之三 · 唯一有素材证据的相关配置

```properties
pvp=true
```

来自 `server.properties`:**全服 PvP 是开着的**
(同一条在 [`06-platforms-and-login.md`](06-platforms-and-login.md) 里也记了)。

⚠️ **但别顺手把这两件事因果连起来。** 素材里没有任何证据说 PvP 是为城堡开的;
反过来,那两份 `castleN_mobs.txt` 说明城堡里**有刷怪清单**,所以这套玩法也完全可能是
"玩家打怪"而不是"玩家互砍"。
**"城堡对战需要 PvP"这句话我拿不出证据** —— [`06`](06-platforms-and-login.md) 那篇也专门把
"`pvp=true` 是为城堡开的"这个推断删掉了。这里跟着一起不猜。

**改的时候注意:`pvp=true` 是全服的,不只城堡那一片。**
哪天为了"防止孩子互殴"把它关掉,**凡是靠玩家互相攻击的玩法都会跟着一起死**,
而且不会有任何报错 —— 只会表现成"孩子互相打不动"。
城堡那套受不受影响,取决于它到底是打人还是打怪(见上)。

## 三、其它玩意儿

任务清单里列了一批插件。我按"素材里有多少证据"分级写,**没有证据的绝不编功能**。

| **faststats** | ? | **零证据**。连它干什么我都不写 | 🔴 未核实 |

### DeluxeMenus:一条已经出过事的规矩

菜单全靠它,所以它的坑最贵。仓库 [`CHANGELOG.md`](CHANGELOG.md) 记了一次 **20 分钟的线上事故**:
同一个格子上放了两个 item(免费按钮 / 付费按钮),**漏写 `priority` 字段**,
结果按钮直接从菜单里消失,孩子反馈"传送按钮没了"。

官方示例里写得很清楚:同一格子有多个 item **必须写 `priority`**,数字小 = 优先级高。

> **菜单是孩子唯一的入口。菜单里少一个按钮,等于那个功能整体下线。**
> 这个错误不会报错,它表现成"什么都没有"。

### LushRewards:关键的不是金额,是断签规则

金额表的完整版属于经济那篇,这里只留两条**改的时候会咬人**的:

```yaml
reward-mode: streak          # 断一天 → 回到第 1 天
allow-reward-stacking: false # 一天只给优先级最高的那一份,不叠加
reset-days-at: -1            # 不做周期重置
streak-bypass: false         # 维护期间也照样断签
```

配上金额(第 1 天 $30 → 第 7 天 **$150「一周奖励」** → 第 30 天 **$600「满月大奖」**),
`streak` 的含义是:**孩子请一天假,600 块的满月大奖从头再来。**

⚠️ 这里有一个**运维层面的坑**,素材已经足够看出来:
`streak-bypass: false`,而这台机器**每天 05:00 JST 定时重启**。
重启本身大概不会算"缺席"(奖励是按玩家上线领取算的),但**一旦哪天服务器长时间停机**,
所有孩子的连签会一起断掉 —— 而 `streak-bypass` 这个开关**存在的理由就是维护期**。
维护前把它临时打开,是一个花 10 秒能避免的集体挫败。
(**"长停机会断掉所有人连签"这一条我没实测过**,是从配置语义推的。)

### Chunky:那个 05:10 的定时任务

素材里关于 Chunky 只有一行:

```
Fri 2026-09-18 05:10:00 JST   mc-chunky-resume.timer → mc-chunky-resume.service
```

和它旁边那行放一起看才有意思:

| 时间 | 任务 |
|---|---|
| 04:00 | `mc-backup` 备份 |
| **05:00** | `mc-restart` **定时重启游戏服** |
| **05:10** | `mc-chunky-resume` 续跑预生成 |

**差 10 分钟。** 我的读法:重启之后有人得把预生成任务**重新推起来**,
而且故意等了 10 分钟(让服务器先起稳)。
49 个世界的地形是**分批、跨重启、慢慢磨**出来的,不是一口气生成的 —— 这和
[`04-resource-worlds.md`](04-resource-worlds.md) 里记的一致。

⚠️ 这一段的**因果是我推的**:素材里只有任务名和时间,**没有** Chunky 的配置原文,
也没有那个 resume 脚本的内容。"为什么需要 resume"这个解释**没核实**。

### ServerLinksZ

```yaml
lang: "en-US"
hints: true
linkCommand: true   # 提供一个 /link 命令
```

`linkCommand: true` 意味着服务器上**有一个 `/link` 命令**能列出网页链接。
这个插件把链接同时挂到客户端的"服务器链接"菜单里(**这句是我的理解**,素材只有配置本身)。

**它和 §一之三 那个缺口直接相关**:如果地图网址挂在这里,那孩子其实有第二条路知道地图 ——
但**素材里没有链接清单的内容**,所以挂了什么我不知道。这是最值得下次去确认的一条。

## 四、这一篇的三件事其实是同一件事

| 东西 | 它的状态在哪儿能看见 | 骗人的地方 |
|---|---|---|
| BlueMap 渲染线程 | 服务器 TPS | **TPS 全程 20.0,玩家全程进不来** |
| 地图网址 | 老麦嘴里 | **说明书写了 ≠ 玩家知道**(说明书里其实也没写) |
| 城堡对战 | 一行 54 秒的重建日志 | **玩法的存亡压在一个脚本上**,而这个脚本我手上一份文档都没有 |

三条共同点:**真实状态和你顺手能看到的那个指标,不是同一个东西。**
第一条要看玩家端不是看 TPS;第二条要看"没问过老麦的孩子"不是看配置;
