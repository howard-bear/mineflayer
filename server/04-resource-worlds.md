# 49 个随机资源世界(ResWorld)

> 本服最大的特色玩法:**主世界只有一个,荒野有 49 个。**
> 孩子在主世界圈地盖房,想挖矿就传送去一片全新的随机荒野,挖完回来 —— 家不受影响。
> 这样主世界的地貌不会被挖成月球表面,而"矿在哪"又永远不是问题。
>
> 这篇记录它对玩家可见的规则、2026-09-17 刚上线的**第 6 次收费**,
> 以及收费上线时我把线上弄坏了 20 分钟的那个**一行字的疏漏**。

## 一、孩子看到的是什么

三条路进去,都通向同一个命令:

| 入口 | 怎么到 | 出处 |
|---|---|---|
| 主菜单 | 手持**指南针**右键 → `/menu` → 「资源世界」(钻石矿石图标,slot 20)→ 子菜单 | 主菜单配置原文(`DIAMOND_ORE` / `slot: 20` / `[openguimenu] resworld`) |
| 直接打命令 | `/res go` | 老麦的固定答案里就是这么教的 |
| 问 AI 村民老麦 | 聊天里提到"资源世界" | 老麦的 `quick-answers` 里有一条专答这个 |

("手持指南针右键"这条也有原文 —— 玩法书里写的是「右键&2指南针&0开菜单」。)

子菜单里那个按钮叫什么,素材里有**间接**证据:老麦的固定答案原话是
「菜单里点「资源世界」→「**前往随机资源世界**」,或者直接打 /res go」。
也就是说子菜单里至少有这么一个按钮 —— 但**子菜单自己的配置文件没抓下来**(见 §四)。

主菜单那一格的原文(显示名是三语,`lore` 只有中文;为了短,省掉了
`hide_attributes` / `hide_enchantments` 两行):

```yaml
  resource:
    material: DIAMOND_ORE
    slot: 20
    display_name: '&b&l资源世界 &r&7Mining &r&8資源'
    lore:
      - '&7全新的荒野 &8矿多树多'
      - '&7每次都随机去一片新地方'
      - ''
      - '&e今天还剩 &f%resworld_left%&e / %resworld_limit% 次'
      - ''
      - '&a▶ 点击打开'
    left_click_commands:
      - '[openguimenu] resworld'
```

发到孩子手里的**玩法书**(`Essentials/book.txt`)里也印了:

```
&2资源世界&0: 随机送你去
一片全新荒野,矿多树多
&c每天5次,不能圈地
&c不能设家,回不到上一个
```

英文版那两行是 `5 trips a day, no claims` / `no /sethome, always new`。

⚠️ **日文版这一句我没看到。** 玩法书里中文、英文、日文三段都有(`✦ 游玩说明 ✦` / `✦ Guide ✦` / `✦ ガイド ✦`),
但抓下来的素材在日文段的「土地保護 / お店」之后就断了 ——
**日文段到底有没有写资源世界,素材证明不了。** 要么去线上读完整的 `book.txt`,要么就当它缺。

> **"回不到上一个"是这个玩法最需要提前说清的一件事。**
> 每次传送都是新的随机点,上一次挖的矿洞、临时搭的箱子,**再也找不回来**。
> 这条写在书里、写在菜单里、老麦也会说 —— 三个地方都写,是因为它一旦被误解,
> 孩子会把东西丢在一个永远回不去的地方。

## 二、参数全表

插件是**自研的 `ResWorld 1.2.1`**(不是市面上任何一个现成插件)。

| 项 | 值 | 为什么这么定 |
|---|---|---|
| 世界数量 | **49** 个 | 够多到"每次都是新地方",又还没到 Multiverse 列表翻不完的程度 |
| 内部世界名 | `res01` ~ `res49` | 写配置、写命令时要用这个 |
| 游戏里显示名 | 「资源世界01」~「资源世界49」 | Multiverse 别名;孩子看到的是这个 |
| 每人每天免费 | `daily-limit: 5` | 见下节 |
| 两次之间最短间隔 | **5 秒** | 防连点/防手抖,不是防刷 |
| OP | 不受限,次数显示 **`∞`** | 管理员要能连续进去看 49 个世界有没有坏 |
| 随机落点离世界边界留白 | **2150 格** | 落点贴边会让人卡在边界墙上、或掉进还没生成的区块 |
| 找安全落点最多试 | **24** 次 | 随机点可能在水里/岩浆里/悬空,试不中就换一个点 |
| 找点整体超时 | **30 秒** | 兜底,超了就告诉玩家失败而不是无限卡住 |
| 世界内禁用命令 | `blocked-commands` **8 条** | 其中确认的 3 条:`sethome` / `setwarp` / `setspawn` |
| 下线再上线 | `return-on-join: false` | **不会**被踢回主世界,下次上线还站在荒野里 |
| 在资源世界里死 | 回**主世界**出生点,**东西不掉** | 死在一个回不去的世界 = 装备永久消失,所以必须兜住 |

⚠️ 上表**左两列的数值是实的**(来自插件配置),但**「为什么这么定」那一列有一半是我事后反推的** ——
当时定这些数的人没留下记录。反推得最没底的是 `2150` 和 `5 秒`:数值确凿,理由是我猜的。

**为什么 `24` 和 `30` 这两个数要一起看。**
24 次尝试和 30 秒超时是一对上下界:如果单次找点平均要 1.5 秒,那 24 次根本跑不完就先撞上 30 秒 ——
`24` 这个数就成了写给自己看的、永远不生效的数字。这和 [`docs/13`](../docs/13-magic-numbers.md)
第一节记的是同一个形状的坑(**内部等待必须小于外部封顶,否则内层逻辑是死代码**)。
**我没有量过单次找点的真实耗时**,所以不知道这一对里到底是哪个先绑死 —— 列进文末未核实。

### 世界数量的交叉验证

素材里抓下来的 Multiverse 列表**只看到「资源世界01」~「资源世界05」**,因为它分页:

```
====[ Multiverse World List ]====
[Page 1 of 7]
world - NORMAL
world_nether - NETHER
world_the_end - THE_END
资源世界01 - NORMAL
...
资源世界05 - NORMAL
```

第 1 页 8 条 × 7 页 ≈ 49~56 个世界,而 `3`(主世界/下界/末地)`+ 49 = 52`,落在区间里,吻合。
这是**推算**,不是逐个数过 49 个;真名 `res01`~`res49` 也来自实现会话,素材里没有目录列表原文。

### 连带的运维成本(这篇不展开)

49 个额外世界不是免费的,素材里能看到两处痕迹:

- BlueMap 的**地图配置文件数 = 55**(≈ 52 个世界 + 若干),也就是资源世界全都上了网页地图
- 每天 05:10 有一个 `mc-chunky-resume` 定时任务 —— 49 个世界的地形预生成是**分批、跨重启续跑**的

`render-thread-count: 2` 这个值不是随便填的(调大会把玩家卡住),但那属于另一篇的内容。

## 三、导出的 PlaceholderAPI 变量

插件对外只导出三个:

| 变量 | 含义 | 已经在哪用了 |
|---|---|---|
| `%resworld_left%` | 今天还剩几次 | 主菜单 lore;**收费按钮的二选一判据** |
| `%resworld_limit%` | 上限(5) | 主菜单 lore |
| `%resworld_worlds%` | 世界总数(49) | 素材里没看到有地方在用 |

`%resworld_left%` 从"给孩子看个数字"变成了**控制流**(决定显示哪个按钮),这一点在下一节会咬人。

## 四、🆕 2026-09-17:第 6 次起收 1 金币

Owner 的原话是"**象征意义的收**" —— 目的不是赚金币,是给"第 6 次"加一点点手感上的成本,
让次数上限从一堵墙变成一个缓坡。

**第 1~5 次:免费。第 6 次起:每次 1 金币。**

### 为什么做在菜单层,而不是改插件

三条理由叠起来,把"改插件"这条路完全堵死了:

| 障碍 | 后果 |
|---|---|
| **插件源码找不到了,只剩编译好的 jar** | 不能加功能,只能在外面包一层 |
| 插件**不依赖 Vault** | 它自己看不到金币、也收不了钱 |
| 超过 `daily-limit` 时插件**硬拒** | 光有钱不行,还得先让它别拒 |

于是实现落在 **DeluxeMenus 菜单层**:菜单看余额、菜单扣钱,
并且在调用 `res go` 之前**临时把"不限次"权限给一下**,跑完再收回 ——
用插件自己的权限开关绕过它自己的硬拒。

### 做法:一个格子,两个按钮

同一个 slot 上放两个 item,靠 `priority` + `view_requirement` 二选一:

| | 免费按钮 | 付费按钮 |
|---|---|---|
| 图标 | `DIAMOND_ORE` 钻石矿石 | `GOLD_INGOT` 金锭 |
| 显示条件 | `%resworld_left%` **≠ 0** | `%resworld_left%` **= 0** |
| 点击门槛 | 无 | `has money` 1 |
| 点击动作 | `res go` | 临时给权限 → `res go` → 收回权限 |

图标选得有讲究:免费按钮沿用主菜单同一个钻石矿石,**付费按钮换成金锭 ——
和主菜单「金币」那一格是同一个图标**,孩子不用读字就知道"这个要花钱"。

结构大致是这样(⚠️ **示意,不是从线上文件抓下来的原文**,权限节点名和条件类型的准确拼写要去读线上那份):

```yaml
items:
  go_free:
    material: DIAMOND_ORE
    slot: <同一格>
    priority: 1                 # 🔴 必须写
    view_requirement:
      requirements:
        still_free:             # %resworld_left% 不等于 0
          ...
    left_click_commands:
      - '[player] res go'
      - '[close]'

  go_paid:
    material: GOLD_INGOT
    slot: <同一格>              # 和上面同一个格子
    priority: 2                 # 🔴 必须写,且数字更大 = 更靠后
    view_requirement:
      requirements:
        used_up:                # %resworld_left% 等于 0
          ...
    left_click_requirement:
      requirements:
        cost:
          type: has money
          amount: 1
    left_click_commands:
      - '[givepermission] <不限次权限节点>'
      - '[player] res go'
      - '[takepermission] <不限次权限节点>'
      - '[close]'
```

## 五、🔴 我漏了 `priority`,按钮直接消失,线上坏了 20 分钟

**第一版我没写 `priority` 字段。**结果不是"显示错了那个按钮",而是
**那一格什么都不显示** —— 孩子的反馈原话是"**传送按钮没了**"。
从上线到发现修好,大约 **20 分钟**,期间谁都去不了资源世界。

DeluxeMenus 自带的配置注释里其实写得很清楚(以下为 `priority` 的取值范围原文):

> `High priority = 1, Lowest priority = 2147483647.`

文档还明确写着两件事:

1. 同一个 slot 放多个 item,靠 `priority` 决定**谁顶上来**;条件不满足时才轮到数字更大的那个
2. **不写 `priority` 就不能写 `permission`** —— 这两个字段在文档里是绑在一起提的

插件自带的「进阶示例」把这个套路写全了,同一个 slot 11 上三个 item:

| priority | 显示条件 | 作用 |
|---|---|---|
| `1` | 套装可用 **且** 有权限 | 正常按钮 |
| `2` | 只有权限 | "冷却中"按钮 |
| `3` | **无条件** | 兜底:"你没权限" |

> **一格多按钮 = 一个 if/else if/else。`priority` 就是那个"else if"的顺序。**
> 不写顺序,不是"随便挑一个",是**整条链子塌掉、那一格变成空气**。
> 而空气在界面上长得和"这个功能被删了"一模一样 —— 孩子就是这么描述的。

### 我们这一版还缺官方推荐的那个兜底

看上面的示例表:第 3 个 item 是**无条件**的兜底。
而我们这一格的**两个按钮都带 `view_requirement`** ——
只要 `%resworld_left%` 返回了任何"既不等于 0、也不能判成不等于 0"的东西
(PAPI 没加载、插件被停、占位符原样吐出来),**两个条件可能同时不成立,那一格又会变成空气**。

这正是 20 分钟事故的同一个后果,只是触发条件换了。
**建议补一个 `priority: 99`、无 `view_requirement` 的兜底按钮**,
文案写"资源世界暂时不可用,去问管理员",至少孩子看到的是一句话而不是一个洞。

### OP 测不出付费按钮

OP 不受次数限制,`%resworld_left%` 给 OP 显示 `∞`。
`∞ ≠ 0` → OP **永远看到免费按钮**。

> **想验证付费那条路,必须拿一个非 OP 的普通账号、把 5 次用完之后再测。**
> Owner 自己的账号是 OP,用它点一百次也测不到收费逻辑。

## 六、两个查证结论(都是"此路不通",但省得下次再走一遍)

**1. 本服 LuckPerms 没挂 PlaceholderAPI 钩子。**
所以 `%luckperms_*%` 这一类变量在本服**用不了** ——
任何"按权限组显示不同按钮"的想法,得走 DeluxeMenus 自己的 `has permission`,不能走占位符。

**2. `%vault_eco_balance%` 和 `/balance` 的数字对不上。**
同一个账号,一边 **5.69**,一边 **$805.68**。差的不是四舍五入,也不是货币符号。
原因没查出来,所以**没敢把余额写进资源世界菜单的说明文字里**
("你还有 X 金币,够再去 N 次"这种话一句都没写)。

⚠️ 但要注意:**主菜单「金币」那一格现在就在用 `%vault_eco_balance%`**(原文 `&e$%vault_eco_balance%`)。
也就是说,如果这个占位符真的不准,孩子在主菜单上看到的余额就是错的。
这条**还没查完**,单独列进文末。

## 七、想照着搭一台 / 半年后要改的话

**搭的顺序**(依赖关系决定的,反了会返工):

1. 先有 Vault + PlaceholderAPI + 一个经济插件,再谈收费
2. 插件侧先把 49 个世界、`daily-limit`、`blocked-commands`、落点参数配好,`/res go` 裸命令能用
3. 确认插件导出的占位符在游戏里**真的能渲染出数字**(`%resworld_left%` 不是原样显示)
4. 最后才做菜单:免费/付费两个按钮 + `priority` + **无条件兜底**

**改的时候踩得到的地雷:**

| 要改的东西 | 注意 |
|---|---|
| 一格多按钮 | **先写 `priority`,再写别的。**漏了它 = 那一格变空气(§五) |
| 次数/价格 | 三个地方的文案都写着"每天5次":**玩法书**、**主菜单 lore**、**老麦的固定答案**。改了规则要三处同改 |
| 已经发出去的玩法书 | **改不了**。菜单「玩法」那一格**右键**会 `kit guide` 补发一本新的 —— 得让孩子自己去右键 |
| 老麦的 `facts` / `quick-answers` | 那份配置由后台「AI 村民」页面**自动生成**,文件头就写着手改会在下次保存时被覆盖 → 要去后台改 |
| 世界名 | 配置里用 `res01`~`res49`,不是孩子看到的「资源世界01」 |
| 加/减世界数量 | 连带 BlueMap 的地图配置和 Chunky 预生成任务,不只是插件配置 |
| 验证收费 | 用**非 OP** 账号,把 5 次用完再测(§五) |

3. **"不能圈地"是怎么实现的没查。** GriefPrevention 的配置里我没看到按世界关闭圈地的开关 ——
   可能在 GP 的世界列表里,也可能是 ResWorld 自己拦的,不知道。
4. **"死了东西不掉"是谁做的没查。** 插件做的,还是 49 个世界都开了 `keepInventory`,没核实。
   ⚠️ 如果是后者,那**新增第 50 个世界时会漏掉这一项**(这种漏法在本服出过前科)。

**这次改动里没验证的:**

5. 🔴 **那 1 金币到底扣没扣,我没有证据。** 我被告知付费按钮上有 `has money 1` 这道门槛 ——
   但 `has money` 在文档里是**检查余额**,不是扣钱;插件自带示例里,扣钱是**另一条 `eco take` 命令**。
   **上线后要拿非 OP 账号记一下点击前后的余额差。** 如果没扣,那"收费"目前是纯装饰。
6. **临时权限会不会漏收回。** `res go` 找落点最多要 30 秒(异步),而 `[takepermission]` 是
   紧跟着下一条就执行的。两个疑问都没测:①收得太早会不会让插件在后续检查时又拒掉;

   真留下了就等于白送无限次。

8. **5 秒最短间隔对付费传送是否同样生效**,没测。
9. **第 6 次之后有没有上限**(理论上有钱就能一直去),没确认。
