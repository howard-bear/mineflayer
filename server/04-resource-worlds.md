# 49 个随机资源世界(ResWorld)

> 本服最大的特色玩法:**主世界只有一个,荒野有 49 个。**
> 孩子在主世界圈地盖房,想挖矿就传送去一片全新的随机荒野,挖完回来 —— 家不受影响。
> 这样主世界的地貌不会被挖成月球表面,而"矿在哪"又永远不是问题。
>
> 这篇记录它对玩家可见的规则、2026-09-17 刚上线的**第 6 次收费**,
> 以及收费上线时我把线上弄坏了 20 分钟的那个**一行字的疏漏**。

## 一、孩子看到的是什么

三条路进去,都通向同一个命令:

| 入口 | 怎么到 | 出处 |
|---|---|---|
| 主菜单 | 手持**指南针**右键 → `/menu` → 「资源世界」(钻石矿石图标,slot 20)→ 子菜单 | 主菜单配置原文(`DIAMOND_ORE` / `slot: 20` / `[openguimenu] resworld`) |
| 直接打命令 | `/res go` | 老麦的固定答案里就是这么教的 |
| 问 AI 村民老麦 | 聊天里提到"资源世界" | 老麦的 `quick-answers` 里有一条专答这个 |

("手持指南针右键"这条也有原文 —— 玩法书里写的是「右键指南针开菜单」(原文带颜色码)。)

子菜单里那个按钮叫什么,素材里有**间接**证据:老麦的固定答案原话是
「菜单里点「资源世界」→「**前往随机资源世界**」,或者直接打 /res go」。
也就是说子菜单里至少有这么一个按钮 —— 但**子菜单自己的配置文件没抓下来**(见 §四)。

主菜单那一格的原文(显示名是三语,`lore` 只有中文;为了短,省掉了
`hide_attributes` / `hide_enchantments` 两行):

```yaml
  resource:
    material: DIAMOND_ORE
    slot: 20
    display_name: '&b&l资源世界 &r&7Mining &r&8資源'
    lore:
      - '&7全新的荒野 &8矿多树多'
      - '&7每次都随机去一片新地方'
      - ''
      - '&e今天还剩 &f%resworld_left%&e / %resworld_limit% 次'
      - ''
      - '&a▶ 点击打开'
    left_click_commands:
      - '[openguimenu] resworld'
```

发到孩子手里的**玩法书**(`Essentials/book.txt`)里也印了:

```
&2资源世界&0: 随机送你去
一片全新荒野,矿多树多
&c每天5次,不能圈地
&c不能设家,回不到上一个
```

英文版那两行是 `5 trips a day, no claims` / `no /sethome, always new`。

⚠️ **日文版这一句我没看到。** 玩法书里中文、英文、日文三段都有(`✦ 游玩说明 ✦` / `✦ Guide ✦` / `✦ ガイド ✦`),
但抓下来的素材在日文段的「土地保護 / お店」之后就断了 ——
**日文段到底有没有写资源世界,素材证明不了。** 要么去线上读完整的 `book.txt`,要么就当它缺。

> **"回不到上一个"是这个玩法最需要提前说清的一件事。**
> 每次传送都是新的随机点,上一次挖的矿洞、临时搭的箱子,**再也找不回来**。
> 一旦被误解,孩子会把东西丢在一个永远回不去的地方。

⚠️ **对着原文数了一遍,这句警告其实只有玩法书说全了。** 三处的口径并不一样:

| 说话的地方 | 原文 | 说清了吗 |
|---|---|---|
| 玩法书 | 「不能设家,**回不到上一个**」/ `no /sethome, always new` | ✅ 说了"回不去" |
| 主菜单 `lore` | 「每次都随机去一片新地方」 | ⚠️ 只说了"是新地方",没说"旧的回不去" |
| 老麦的固定答案 | 「每次去的都不一样」 | ⚠️ 同上 |

也就是说:**只看菜单、不读书的孩子,没有被明确警告过东西会丢。**
这是个真实的措辞缺口 —— 补的成本只是给主菜单那一格的 `lore` 加一行。

## 二、参数:哪些有原文,哪些只是记忆

先说这个插件本身。素材能证明的只有三件事:

- 命令前缀是 `/res`(老麦的固定答案里有 `/res go`)
- 子菜单名叫 `resworld`(主菜单原文 `[openguimenu] resworld`)
- 导出的占位符以 `resworld_` 开头(主菜单 `lore` 原文)

**除此之外,关于这个插件的一切 —— 正式名字、版本号、是不是自研 —— 抓取的素材里都没有。**
插件名和版本**已核实**,出处是 jar 包里的 `plugin.yml` —— 它不在本篇引用的那四份素材里,
所以校验时曾被标成「未核实」。这里把出处补上:

```yaml
name: ResWorld
version: '1.2.1'
main: jp.laogai.resworld.ResWorld
api-version: '1.21'
author: 2sheep                                   # 自研,不是第三方插件
softdepend: [PlaceholderAPI, Multiverse-Core]    # 注意:没有 Vault
```

`softdepend` 里**没有 Vault** 这一条很要紧 —— 它解释了为什么「第 6 次起收 1 金币」
只能加在菜单层而不是加进插件:插件根本接不到经济系统。

### 素材里有原文的(可以直接引用)

| 项 | 值 | 出处 |
|---|---|---|
| 世界总数 | **49** 个 | 老麦 `facts`「全服49个」;`quick-answers`「全服一共49个」 |
| 每人每天次数 | **5** 次 | 玩法书「每天5次」;老麦「每人每天限5次」;英文版「5 trips a day」 |
| 里面不能圈地 | 是 | 玩法书「不能圈地 / no claims」;老麦「里面不能圈地」 |
| 里面不能设家 | 是 | 玩法书「不能设家 / no /sethome」 |
| 每次都是新地方、回不到上一个 | 是 | 玩法书「回不到上一个 / always new」;老麦「每次去的都不一样」 |
| 主世界的家不受影响 | 是 | 老麦「但你主世界的家一点都不受影响」 |
| 游戏里显示名 | 「资源世界01」…(素材只看到 01~05) | Multiverse 世界列表第 1 页 |
| 剩余次数会实时显示给玩家 | 是 | 主菜单 `lore`:`今天还剩 %resworld_left% / %resworld_limit% 次` |

### ⚠️ 下面这些素材里**没有**(全部来自实现会话的记忆,未核实)

| 项 | 记忆里的值 | 想用之前必须先做的事 |
|---|---|---|
| 内部世界名 | `res01` ~ `res49` | 素材里只有中文显示名,没有世界目录名 —— 先 `/mv list` 或看世界目录 |
| 每天次数的配置键 | `daily-limit: 5` | **值 5 有原文,键名没有** |
| 两次之间最短间隔 | 5 秒 | 🔴 素材里唯一的 `cooldown-seconds: 5` 属于**空岛传送插件 YangPortal**,不是这个插件 —— 很可能是我记串了 |
| OP 不受次数限制、显示 `∞` | 是 | 它撑着 §五 的测试结论,值得优先核实 |
| 随机落点离世界边界留白 | 2150 格 | 读线上插件配置 |
| 找安全落点最多重试 | 24 次 | 读线上插件配置 |
| 找点整体超时 | 30 秒 | 读线上插件配置 |
| 世界内禁用命令 `blocked-commands` | 8 条,只记得 3 条:`sethome` / `setwarp` / `setspawn` | 「不能设家」在玩法书里有原文,但**靠什么实现的没核实** |
| 下线再上线不会被踢回主世界 | `return-on-join: false` | 读线上插件配置 |
| 在资源世界里死:回主世界出生点、东西不掉 | 是 | 死在一个回不去的世界 = 装备永久消失,所以这条**必须**核实 |

**为什么把这一整块降级成"未核实",而不是照记忆写成一张漂亮的表。**
上一版这张表写着「左两列的数值是实的(来自插件配置)」——
可抓取的四份素材里**根本没有这个插件的配置文件,一行都没有**,
那句"是实的"本身就是个没有出处的断言。
而 `cooldown-seconds: 5` 那一条正好说明危险在哪:素材里确实有这个数,但它属于**另一个插件**。
凭记忆写参数表,就会把隔壁插件的参数搬过来,而且搬过来之后长得和真的一模一样。

**顺带记一个当时想到、但同样没法证实的隐患。**
如果"最多重试 24 次"和"整体超时 30 秒"这两个数真是记忆里那样,它们就是一对上下界:
单次找点只要平均超过 1.25 秒,24 次就永远跑不完 —— `24` 会变成一个永不生效的数字。
这和 [`docs/13`](../docs/13-magic-numbers.md) 第一节是同一个形状的坑
(**内部等待必须小于外部封顶,否则内层逻辑是死代码**)。
但**两个数本身都没核实,我也没量过单次找点耗时**,所以这只是一条"核实之后要顺手检查"的提醒。

> **没有原文的数字,写进文档就会被当成事实引用。**
> 这一节宁可难看,也不能让半年后的自己拿一串没出处的数去改线上配置。

### 「49」这个数有两条独立证据

**第一条:服务器自己说的。** 老麦的配置里两处写着 49(`facts` 的「全服49个」、
`quick-answers` 的「全服一共49个」)。这是服务器**对孩子的口径**,不是我推的。

**第二条:Multiverse 列表的页数,能对上。** 抓下来的列表**只看到第 1 页**,因为它分页:

```
====[ Multiverse World List ]====
[Page 1 of 7]
world - NORMAL
world_nether - NETHER
world_the_end - THE_END
资源世界01 - NORMAL
资源世界02 - NORMAL
资源世界03 - NORMAL
资源世界04 - NORMAL
资源世界05 - NORMAL
```

第 1 页 8 条 × 7 页 ⇒ 总数落在 **49~56** 之间;而 `3`(主世界/下界/末地)`+ 49 = 52`,在区间里,吻合。

⚠️ 但**没有任何素材逐个列出过 49 个世界** —— 两条证据一条是"服务器的口径"、
一条是"页数区间",都不是完整清单。要真数一遍,得把 `/mv list` 七页全翻出来。
世界的**目录真名**(记忆里是 `res01`~`res49`)同样没有原文。

### 连带的运维成本(这篇不展开)

49 个额外世界不是免费的,素材里能看到两处痕迹:

- BlueMap 的**地图配置文件数 = 55**(素材里就是这个数)。52 个世界 + 3,数量级对得上,
  合理的读法是资源世界也都上了网页地图 —— 但**我没逐个打开那 55 个配置确认**
- 每天 05:10 有一个 `mc-chunky-resume` 定时任务(`systemctl list-timers` 原文)。
  从名字看,地形预生成是分批、跨重启续跑的;**"resume" 具体在做什么我没读那个脚本,这是从名字推的**

BlueMap 的 `render-thread-count` 现在是 **2**(素材里的原文)。
这个值和"49 个世界都要渲染"是直接相关的,但**它为什么是 2、调大了会怎样**属于地图那一篇,
这里不展开、也不替它下结论。

## 四、🆕 2026-09-17:第 6 次起收 1 金币

> ⚠️ **这一整节的出处是今天做这件事的第一人称记录,不是抓取的配置原文。**
> 资源世界子菜单(`resworld`)的配置文件**没抓下来**,所以下面的结构、字段名、权限节点
> 都得去线上那份文件核对才算数。
> 素材唯一能证明的是:主菜单里确实有 `[openguimenu] resworld` 这一行 —— 即这个子菜单存在。

Owner 的原话是"**象征意义的收**" —— 目的不是赚金币,是给"第 6 次"加一点点手感上的成本,
让次数上限从一堵墙变成一个缓坡。

**第 1~5 次:免费。第 6 次起:每次 1 金币。**

### 为什么做在菜单层,而不是改插件

三条理由叠起来,把"改插件"这条路完全堵死了:

| 障碍 | 后果 |
|---|---|
| **插件源码找不到了,只剩编译好的 jar** | 不能加功能,只能在外面包一层 |
| 插件**不依赖 Vault** | 它自己看不到金币、也收不了钱 |
| 超过每天上限时插件**硬拒** | 光有钱不行,还得先让它别拒 |

⚠️ 这三条都是当时的判断,**素材里没有任何对应证据** ——
既没有 jar/源码清单,也没有 `/plugins` 输出,更没有插件文档。
"不依赖 Vault""硬拒"这两条尤其值得回头核实,因为整个方案是建立在它们之上的。

于是实现落在 **DeluxeMenus 菜单层**:菜单看余额、菜单收钱,
并且在调用 `res go` 之前**临时把"不限次"权限给一下**,跑完再收回 ——
用插件自己的权限开关绕过它自己的硬拒。

🔴 **"菜单收钱"这一步是本篇最可疑的地方。** 目前能说的只是"按钮上挂了一个余额门槛",
**至于金币有没有真的从账上扣掉,我没有证据** —— 详见文末 C13,那是上线后第一件该验的事。

### 做法:一个格子,两个按钮

同一个 slot 上放两个 item,靠 `priority` + `view_requirement` 二选一:

| | 免费按钮 | 付费按钮 |
|---|---|---|
| 图标 | `DIAMOND_ORE` 钻石矿石 | `GOLD_INGOT` 金锭 |
| 显示条件 | `%resworld_left%` **≠ 0** | `%resworld_left%` **= 0** |
| 点击门槛 | 无 | `has money` 1 |
| 点击动作 | `res go` | 临时给权限 → `res go` → 收回权限 |

图标选得有讲究:免费按钮沿用主菜单同一个钻石矿石,**付费按钮换成金锭 ——
和主菜单「金币」那一格是同一个图标**,孩子不用读字就知道"这个要花钱"。

结构大致是这样(⚠️ **示意,不是从线上文件抓下来的原文**,权限节点名和条件类型的准确拼写要去读线上那份):

```yaml
items:
  go_free:
    material: DIAMOND_ORE
    slot: <同一格>
    priority: 1                 # 🔴 必须写
    view_requirement:
      requirements:
        still_free:             # %resworld_left% 不等于 0
          ...
    left_click_commands:
      - '[player] res go'
      - '[close]'

  go_paid:
    material: GOLD_INGOT
    slot: <同一格>              # 和上面同一个格子
    priority: 2                 # 🔴 必须写,且数字更大 = 更靠后
    view_requirement:
      requirements:
        used_up:                # %resworld_left% 等于 0
          ...
    left_click_requirement:
      requirements:
        cost:
          type: has money
          amount: 1
    left_click_commands:
      - '[givepermission] <不限次权限节点>'
      - '[player] res go'
      - '[takepermission] <不限次权限节点>'
      - '[close]'
```

🔴 **这里有一个必须核对的矛盾点。**
`[givepermission]` / `[takepermission]` 这两个动作,
在抓取到的 DeluxeMenus 自带注释里那份"合法 click_command 前缀"清单上**并不存在**。
那份清单的原文只列了:
`[console]` `[player]` `[commandevent]` `[message]` `[openguimenu]`
`[connect]` `[close]` `[refresh]` `[broadcastsound]` `[sound]` `[json]`。

两种可能,素材分不出是哪种:① 本服的 DeluxeMenus 比那段注释新
(自带注释不一定跟着代码更新);② 这条路根本不成立,当时写的是别的形式
(例如用 `[console]` 去调 LuckPerms 的命令)。
**去线上读那份 `resworld` 菜单文件,是验证整个 §四 的第一步。**

## 五、🔴 我漏了 `priority`,按钮直接消失,线上坏了 20 分钟

**第一版我没写 `priority` 字段。**结果不是"显示错了那个按钮",而是
**那一格什么都不显示** —— 孩子的反馈原话是"**传送按钮没了**"。
从上线到发现修好,大约 **20 分钟**,期间谁都去不了资源世界。

DeluxeMenus 自带的配置注释里其实写得很清楚(以下为 `priority` 的取值范围原文):

> `High priority = 1, Lowest priority = 2147483647.`

文档还明确写着两件事:

1. 同一个 slot 放多个 item,靠 `priority` 决定**谁顶上来**;条件不满足时才轮到数字更大的那个
2. **不写 `priority` 就不能写 `permission`** —— 原文是 `You CAN NOT specify a permission without a priority!`

⚠️ 第 1 条的方向,素材里的措辞其实是**自相矛盾**的:同一份注释一边写
`High priority = 1`,一边在 `view_requirement` 那行写
"…the **lowest** priority item a player meets all view requirements for will be shown"。
按字面读,一句说 1 号先上,一句说号大的先上。
我采信的是**它自带示例的实际写法**(`priority: 1` 是条件最全的那个,`3` 是无条件兜底),
而不是那句话 —— 但这属于**按示例反推**,不是文档明说的。

插件自带的「进阶示例」把这个套路写全了,同一个 slot 11 上三个 item:

| priority | 显示条件 | 作用 |
|---|---|---|
| `1` | 礼包(kit)可用 **且** 有权限 | 正常按钮 |
| `2` | 只有权限 | "冷却中"按钮 |
| `3` | **无 `view_requirement`** | 兜底:"你没权限" |

> **一格多按钮 = 一个 if/else if/else。`priority` 就是那个"else if"的顺序。**
> 不写顺序,不是"随便挑一个",是**整条链子塌掉、那一格变成空气**。
> 而空气在界面上长得和"这个功能被删了"一模一样 —— 孩子就是这么描述的。

### 我们这一版还缺官方推荐的那个兜底

看上面的示例表:第 3 个 item 是**无条件**的兜底。
而我们这一格的**两个按钮都带 `view_requirement`** ——
只要 `%resworld_left%` 返回了任何"既不等于 0、也不能判成不等于 0"的东西
(PAPI 没加载、插件被停、占位符原样吐出来),**两个条件可能同时不成立,那一格又会变成空气**。

这正是 20 分钟事故的同一个后果,只是触发条件换了。
**建议补一个 `priority: 99`、无 `view_requirement` 的兜底按钮**,
文案写"资源世界暂时不可用,去问管理员",至少孩子看到的是一句话而不是一个洞。

### OP 测不出付费按钮

**前提(⚠️ 未核实,来自记忆):** OP 不受次数限制,`%resworld_left%` 给 OP 显示 `∞`。
如果真是这样,`∞ ≠ 0` → OP **永远看到免费按钮**。

> **想验证付费那条路,必须拿一个非 OP 的普通账号、把 5 次用完之后再测。**
> Owner 自己的账号是 OP,用它点一百次也测不到收费逻辑。

这条结论的方向大概率是对的(OP 不受限是这类插件的常规做法),
但"显示 `∞`"这个具体表现**素材里没有原文**。
真要验证,顺手做的第一件事就是:拿 OP 和非 OP 各看一眼那一格,把 `%resworld_left%` 的实际取值记下来。
