# 06 · 能用什么设备玩,以及怎么登录

> 这台服务器的服务端**锁在 Minecraft Java 1.21.4**(这个版本号的证据是间接的,见第三节),
> 而实际连上来的有:电脑 Java 版、手机和主机的**基岩版**、以及**版本号比服务端高出一大截**的客户端
> (抓取那一刻在线的是 `26.1-26.1.2` 和 `26.2`)。
> 它还跑在**离线模式**(`online-mode=false`)下 —— 也就是服务端自己没法验证"你是不是你"。
>
> 这几件事没有一件是服务端原生支持的,全靠插件顶着。这一篇就是把"谁顶哪一段"列清楚。

> 🔴 **先说清这一篇的证据边界,因为它和别的篇不一样。**
> 属于"现场证据"的只有四样:`server.properties` 的输出、`viaversion list` 的输出、
> 孩子那本书的原文、以及 YangPortal / GriefPrevention 的配置片段 —— 都是 2026-09-17 抓的。
> **插件清单和版本号不在这批素材里**:在四份 `raw-*.txt` 里 grep
> `Geyser` / `Via` / `nLogin` / `FreedomChat` / `Grim`,**零命中**。
> 它们来自 [`CHANGELOG.md`](CHANGELOG.md) 和 [`docs/09`](../docs/09-plugins-and-ports.md) 那样的运维记录。
> 所以:**插件名当线索看,版本号一律以服务器上 `/plugins` 的实际输出为准。**

## 一、先看结论:六个缺口,六个补丁(外加一个反作弊)

| 玩家从哪来 | 服务端缺什么 | 谁补上 |
|---|---|---|
| Java 版,正好 1.21.4 | 什么都不缺 | 直连 |
| Java 版,**比 1.21.4 新** | 协议号对不上,直接被拒 | **ViaVersion** ¹ |
| Java 版,**比 1.21.4 老** | 协议号对不上(反方向) | **ViaBackwards** ¹ |
| 手机 / 主机 **基岩版** | 协议完全是另一套 | **Geyser** ² |
| 基岩玩家**没有 Java 账号** | 服务端不认识这个身份 | **Floodgate** ² |
| 离线模式下的任何人 | 服务端没法验证身份 | **nLogin**(自己设登录口令)² |
| 离线模式下的聊天 | 消息没有签名 → 客户端弹提示 | **FreedomChat** ² |
| (顺带)作弊客户端 | —— | **GrimAC** ³ |

¹ 现场素材只证明了"**有一层版本翻译在干活**"(第四节),**"这层是 Via" 是推断,不是证据** ——
和 [01 篇](01-what-players-see.md) 的口径一致。
² 出自 [`CHANGELOG.md`](CHANGELOG.md);那份记录自己在这一段上标了"来自助手的笔记,日期未逐条复核"。
³ 出自 [`docs/09`](../docs/09-plugins-and-ports.md) —— 那一篇是在这台服上实测机器人时写的("真的装着 GrimAC")。

**为什么要这么堆:** 这台服务器面向的是一群中学生(老麦的人设里写着"十几岁的中学生,16 岁上下"),
他们手上的设备是**给定条件**,不是可以要求的。
有人用电脑,有人只有手机,有人用主机 —— 书里写的就是"手机/主机 基岩版" —— 而客户端会自己悄悄升级。
所以"兼容"这一层不是加分项,是**能不能进来玩**的问题。

## 二、地址和端口(这两行是印在孩子拿到的书里的)

`plugins/Essentials/book.txt` 原文:

```
&1&l✦ 服务器地址 ✦
&0中国大陆 CN
&2cn.laogaiphoto.com
&0日本 · 海外 JP
&2mc.laogaiphoto.com

&8手机/主机 基岩版:
&8端口填 &219132

```

| 入口 | 给谁 | 怎么填 |
|---|---|---|
| `cn.laogaiphoto.com` | 中国大陆 | Java 直接连;基岩版端口 `19132` |
| `mc.laogaiphoto.com` | 日本 / 海外 | 同上 |
| 地图网站 `map.v2good.com` | 所有人(浏览器) | 老麦的原话:「打开网站 map.v2good.com 就能看整个世界的地图,还能看到大家现在在哪儿」 |

**Java 版的端口书里没写**,大概是因为用的就是默认端口 —— 但请注意证据的强度:
素材里**没有** `server.properties` 的 `server-port` 那一行,只有 YangPortal 配置里的 `port: 25565`
(那是那个插件自己的字段,不等于服务端监听口)。所以"Java 走 25565"是**合理推断**,不是抄来的。
**基岩版必须手填 `19132`**,这个数字是书里明写的;它和 Java 的端口完全是两个东西。

两个域名分别指向不同的后端(**具体后端主机名不进这个公开仓库**)。为什么要分两个入口、
中国大陆那条链路是怎么走的,不在这一篇的范围里。

所以**服务端 jar 的品牌和精确版本,这次没有证据**。

## 四、客户端版本:服务端锁死,翻译交给 Via

| 插件 | 管哪个方向 | 版本 |
|---|---|---|
| ViaVersion | 客户端**比服务端新** → 让新客户端能连老服务端 | **没抓到** |
| ViaBackwards | 客户端**比服务端老** → 让老客户端能连新服务端 | **没抓到** |

⚠️ 这张表里**唯一算证据的是下面那段 `viaversion list` 的输出** ——
它证明"服务器上确实有一个认识 `viaversion` 这个命令的东西"。
**两个插件的版本号,这次一个都没抓到**,任何具体数字都请去服务器上敲 `/plugins` 查。

### 实测:三个客户端同时在线,报的是三个不同的版本

服务器控制台执行 `viaversion list`,输出如下
(玩家名按本仓库惯例脱敏、列宽对齐过;**版本号和人数原样未改**):

```
[1.21.4]          (1): [<PLAYER>]
[26.1-26.1.2]     (1): [XiaoMai]
[26.2]            (1): [<OWNER>]
```

`XiaoMai` 就是这个仓库的主角 —— 那个 mineflayer 机器人。

**这三行输出是整篇里最硬的一条证据:** 同一时刻,一个 1.21.4 的客户端、一个 26.1.x、
一个 26.2,**三个协议族同时挂在一台锁 1.21.4 的服务端上** —— 说明翻译层确实在干活,
不是"装了但没生效"。

三条必须说清的限制:

1. **素材只证明了"客户端比服务端新"这一个方向。** 比 1.21.4 **老**的客户端(那才是
   ViaBackwards 的活)这次**一个样本都没有**。这份证据既没验证 ViaBackwards,
   也没证明它在这台服上存在 —— 它出现在这篇里,靠的是运维记录。
2. **`viaversion list` 报的是客户端自称的版本,不是服务端的版本。** 别把
   `[26.2]` 读成"服务端升到 26.2 了"。
3. **机器人被报成 `26.1-26.1.2`,我解释不了。** 它在代码里是按 1.21.4 连的
   (`docs/` 里那些实测都是 1.21.4 的数据)。这条留作未核实,别拿它推断什么。

### ⚠️ 运维经验:Via 落后于孩子的客户端 → 症状是「一传送就闪退」

这条是**运维记录里写着"真的踩过"**的一条(不在本次抓取的素材里,所以下面这段症状描述我没法自己复核):
孩子的客户端自动升级到一个 ViaVersion 还没支持的版本时,
表现出来的**不是**"连不上",而是 —— **能进服、能走路、一传送就闪退**。

所以它很容易被误诊成传送插件坏了、世界坏了、或者"网不好"。

**一秒钟的诊断方法:**

```
# 服务器控制台 / RCON
viaversion list
```

- 看得到孩子的名字、且版本号是个**已知的**版本 → 翻译层在工作,问题在别处
- 名字根本不出现,或者版本号是个没见过的数字 → **先升 ViaVersion / ViaBackwards**

**为什么偏偏是"传送"这个动作炸,我没有抓到包级证据** —— 只有症状和处置。
合理的猜测是传送时要重发一批区块/维度数据,翻译层在那里露馅;但这只是猜测,别当结论。

> **锁死服务端版本 ≠ 冻结了客户端版本。**
> 客户端会**自己**升级,而且不会问你。所以"服务端不动"这个决定,
> 实际上是把一份**持续的维护义务**转移到了 Via 这两个插件上 ——
> 谁都不动的那一天,兼容性就自己坏了。

## 五、基岩版(手机 / 主机):Geyser + Floodgate

| 插件 | 干什么 |
|---|---|
| **Geyser** | 监听基岩版协议,翻译成 Java 版协议喂给服务端 |
| **Floodgate** | 让**没有 Java 账号**的基岩玩家也能被服务端接受为一个玩家身份 |

两个必须一起装:Geyser 解决"话听不懂",Floodgate 解决"人不认识"。只装前一个,
基岩玩家会在身份这一步被拒。

**素材里有据的只有 `19132` 这个端口**(书里明写),以及"手机/主机 基岩版"这句话。
"这两个插件叫 Geyser 和 Floodgate"出自 [`CHANGELOG.md`](CHANGELOG.md);
**具体是哪个发行版(Geyser-Spigot / Geyser-Standalone / 代理端),素材和记录里都没写。**

**孩子那边要做的只有一件事:** 地址照抄,**端口改成 19132**。
Java 版玩家什么都不用填。

**改这块之前要知道的两件事**(都记在 [`server/CHANGELOG.md`](CHANGELOG.md),
那份记录本身标了"来自助手记忆、未逐条复核"):

- 开基岩版时要同时关掉 Paper 的 `perform-username-validation`,并**放宽 nLogin 的名字正则** ——
  否则**带点号的名字进不来**。基岩版的玩家名允许空格和符号,Java 那套 `[A-Za-z0-9_]` 的假设在这里不成立。
- **Geyser 版本落后会直接导致孩子连不上。** 基岩版客户端是应用商店自动更新的,
  它比 Java 客户端更不受你控制。

## 六、离线模式 + nLogin:登录是怎么走的

`online-mode=false` 换来"没有正版账号也能玩",代价是三件事同时出现:

| 后果 | 具体表现 | 怎么兜住的 |
|---|---|---|
| 服务端不验证身份 | 任何人都能用**别人的名字**进服 | **nLogin**:自己注册一个登录口令(`CHANGELOG.md` 记的是 2026-07-19 换成 **2.0.18**,本次没复核) |
| UUID 变成离线 UUID | 玩家数据、商店归属、权限全部挂在离线 UUID 上 | 见下面的 ⚠️ |
| 聊天消息没有签名 | 客户端弹「无法验证聊天消息」 | **FreedomChat**(第七节) |

### 孩子第一次进服要打的两条命令

```
/register <自己定的口令> <再打一遍>
/login <自己定的口令>
```

之后每次进服只需要 `/login`。**顺序是先 `/register` 再 `/login`** ——
没注册就去登录是进不去的。

⚠️ **这两条命令的名字来自运维记录**(`CHANGELOG.md` / `server/README.md` 都写的是
`/register` → `/login`),**参数怎么写则是按 nLogin 常见用法填的,本次没有实测** ——
口令要不要打两遍,以插件自己在聊天框里的提示为准。

### 从别的服回来时免登录:YangPortal 的通行证

`YangPortal` 的配置里,**和登录有关的几行**(原文顺序,中间跳过了密钥和后端主机名 ——
那两样不进公开仓库):

```yaml
port: 25565
cooldown-seconds: 5
check-interval-seconds: 20
default-return-host: mc.laogaiphoto.com

# 从 Strix 回来时凭签名通行证免密码登录
auto-login-on-return: true
```

也就是:孩子从菜单里跳去另一台服(Strix:主大厅 / 生存世界 / 空岛世界),**回来时不用再打一次 `/login`** ——
凭一张签名过的通行证放行。`cooldown-seconds: 5` 是两次跳转之间的冷却,
`check-interval-seconds: 20` 是探活间隔。

**我只看到了这份配置,没有实测过这条链路现在通不通。** 另外世界传送菜单自己写着
「背包和金币不会带过去 / 那边是独立的存档」—— 所以这张通行证省掉的只是**登录这一步**,
身份和家当仍然是**按服分开**的。

### ⚠️ 同一个 IP 能同时进几个人

`GriefPreventionData/config.yml` 里抓到这两个值(在原文里**不相邻**,是我摘到一起的):

```
MaxPlayersPerIpAddress: 3
LoginLogoutNotificationsPerMinute: 5
```

只有**上面那一行**是人数限制。下面那行管的是"每分钟最多播几条进出服提示",
和能不能进来无关 —— 放在这里只是因为它是同一份配置里唯一另一条带 `Login` 的值。

**这一条在"很多孩子从同一个出口 IP 进来"的场景下会咬人** ——
第 4 个人会被挡住。**具体会看到什么报错,我没有样本**(所以别指望从报错文字里认出这是人数限制)。
如果你的玩家是通过某个共享出口进来的,这个数字要么调大,要么把那个出口加白。

**再强调一次:素材里没有任何"有人被这条限制挡住"的记录。** 我只抓到了这个值,
"它在这台服上实际怎么表现"没有任何证据。

### ⚠️ 离线 UUID 这条不要轻易碰

`online-mode` **改回 `true` 不是一个可逆操作**:所有玩家数据都建在离线 UUID 上,
翻回正版模式等于所有人换了一个身份 —— 商店归属、权限、家、领地都会对不上。
**这一条不在本次抓取的素材里**(素材只有 `online-mode=false` 这一行事实),
它来自运维记录,照做前请自己验一遍。

## 七、FreedomChat:治「无法验证聊天消息」那个提示

**成因:** 离线模式下服务端没有 Mojang 那套密钥去给聊天消息签名,
客户端一进服就弹一个"无法验证聊天消息"的提示。**功能上什么都没坏**,
但对一个十几岁的玩家来说,进门第一眼看到一个警告框,体验是实打实的差。

**运维记录里写的是 FreedomChat 1.7.2**([`CHANGELOG.md`](CHANGELOG.md)),
本次抓取**既没抓到这个插件,也没抓到那条提示的现场记录** —— 这一整节都建立在那份记录上。

两条改它的时候要注意的(同样记在 [`server/CHANGELOG.md`](CHANGELOG.md),那里标了未复核):

- 光装上不够,**必须把 `claim-secure-chat-enforced` 设成 `true`**(默认是 `false`)
- 它**没有 reload 命令**,改完要**完整重启**服务端才生效

> 这是这篇里最能说明"离线模式的代价是零碎的"的一个例子:
> 它不是一个 bug,没有报错、没有日志,只是**每个孩子每次进服都会看到一个警告**。
> 这种问题不会出现在任何监控里,只会出现在"孩子觉得这服是不是有问题"里。

## 九、想照着搭一台:顺序和每一步的坑

顺序是有依赖的,装反了会得到一堆看起来无关的故障:

| 顺序 | 装什么 | 装完先验什么 | 这一步的坑 |
|---|---|---|---|
| 1 | 服务端锁一个版本(这台是 1.21.4) | 自己用同版本客户端能进 | 锁版本会让**其它插件**的版本也被锁死 —— `CHANGELOG.md` 里记着"EssentialsX 固定 2.21.0,2.22.0+ 放弃了 1.21.4 支持"(那条同样标了未逐条复核) |
| 2 | ViaVersion + ViaBackwards | `viaversion list` 能看到自己,版本号正确 | **这两个要持续更新** —— 落后的症状是「一传送就闪退」,不是"连不上" |
| 3 | nLogin(**在开放注册之前**) | `/register` → `/login` 走通 | 离线模式下**先开服再装登录插件** = 那段时间任何人可以冒用任何名字 |
| 4 | Geyser + Floodgate | 手机填 `19132` 能进 | 名字正则 / username validation 会挡掉带点号的基岩名 |
| 5 | FreedomChat | 进服**没有**那个警告提示 | 要设 `claim-secure-chat-enforced: true`,而且**得完整重启** |
| 6 | GrimAC | —— | 反作弊和 `allow-flight=false` 是两套判定,别互相替代 |

> **这一整套的本质是:服务端只锁定了一件事(版本),其余全是"把外面的世界翻译进来"。**
> 翻译层有三处(协议、身份、聊天),它们**各自**都会因为外部世界自己变化而失效 ——
> 客户端自动升级、应用商店推基岩版更新、孩子换设备。
>
> 所以这篇里最该记住的不是插件清单,是那条运维经验:
> **兼容性不是"配好了就完事",它是一件会自己坏掉的事。**
> 而它坏掉时的症状(一传送就闪退、带点号的名字进不来、进门一个警告框)
> **全都不长得像版本问题**。
