# 这些文档是怎么写出来的(以及为什么)

> 这是一篇**元文档** —— 不讲服务器的任何功能,只讲 `server/` 这批文档的来源、纪律和红线。
>
> 它存在的理由和 [`CHANGELOG.md`](CHANGELOG.md) 是同一句话,Owner 的原话:
>
> > **「以后好查询 不然你很快就会失忆的」**
>
> 短,但它是这整个目录的地基。下面把这句话拆成可执行的四条规矩,
> 再记一条**今天现场吃到的**教训 —— 它的形状和这批文档的写法直接相关。

---

## 一、为什么非要有这个目录

维护这台服务器的是 AI 助手,而助手的**会话记忆会被压缩**。
今天花两个小时查清的东西(某个配置在哪个文件、某个数字为什么是这个值、上一次回滚怎么做的),
下一次会话可能完全不在上下文里。人会忘,但至少忘得慢;助手是**每一次都可能从零开始**。

于是有一条硬规矩:

> **服务器的任何改动,都要落到仓库里。** 不落仓库的改动,等于没做过 ——
> 它还在线上跑,但没有人知道它为什么在、怎么关掉。

不写下来的代价不是抽象的,是这四样具体的东西:

| 丢掉的东西 | 下一次要付的代价 |
|---|---|
| 改了哪个文件 | 重新翻一遍服务器的插件目录去找 |
| 为什么这么改 | 不敢改回去,也不敢往上加东西 |
| 怎么回滚 | 出事的时候现场推理,而那是最不该推理的时刻 |
| 试过什么此路不通 | **重新把同一条死路再走一遍**(最贵的一项) |

**这个目录里已经有一块"失忆的化石"。**
`CHANGELOG.md` 末尾那一节标着「更早的改动(**日期未逐条复核**)」——
那些条目是从助手的笔记里整理的,不是当场从服务器验的,所以只能整段打上"引用前请自己确认一次"。
这就是没有当场落笔的结果:内容还在,但**可信度已经降级了**,再也升不回来。

## 二、写作纪律:每一条都要有出处

`server/` 这批文档的素材是**当场从服务器抓下来的原文**,不是凭印象写的。
抓下来的东西大致是这几类:

| 素材类型 | 里面有什么 |
|---|---|
| `server.properties` | 难度、模式、在线模式、视距等服务器规格 |
| Multiverse 世界列表 | 世界的内部名和显示名 |
| Jobs 职业清单 | 12 个职业、最高等级、当前在职人数 |
| 插件配置原文 | GriefPrevention / ResWorld / LushRewards / AI 村民 等的数值 |
| DeluxeMenus 菜单 YAML | 孩子按指南针真正看到的每一格:图标、slot、三语文案、点击执行的命令 |
| 发给孩子的玩法书 | `Essentials/book.txt` 的三语原文 |

在这些原文之上,只有三条纪律:

| 纪律 | 具体怎么做 |
|---|---|
| **1. 只写素材里有据的** | 数值一律抄原文;抄的时候尽量连上下文一起贴(YAML 片段、命令输出),让下一次能自己判断 |
| **2. 素材里没有的,要么不写,要么明说** | 每篇结尾都有一节 **「⚠️ 这篇里我没核实的」**,老实列出来 —— 这一节不是客套,是文档的一部分 |
| **3. 分清"抄的"和"推的"** | 数值是抄的,**理由常常是事后反推的**,两者不能混在一起讲 |

第 3 条最容易含糊,所以在文档里是显式标出来的。三种确定度长这样:

| 确定度 | 例子(出自 [`04-resource-worlds.md`](04-resource-worlds.md)) |
|---|---|
| **原文抄下来的** | `daily-limit: 5`、落点留白 `2150` 格、找点最多试 `24` 次 —— 数值确凿 |
| **推算的** | 「49 个资源世界」是按 Multiverse 列表 7 页推算的(素材里**只看到 01~05**,因为它分页),**不是逐个数过** |
| **事后反推的** | 参数表里「为什么这么定」那一列**有一半是我反推的** —— 当时定这些数的人没留下记录 |

> **"我知道这个数"和"我知道这个数为什么是它"是两件事,文档里必须分开写。**
> 把反推的理由写成既成事实,下一个人就会拿它当约束,不敢动一个本来可以动的数。

顺带一条关于素材本身的:**命令输出会分页、会截断。**
Multiverse 列表只给了第 1 页,RCON 查背包会截断([`docs/10`](../docs/10-counting-deaths.md) 里记过)。
所以"素材里没看到"不等于"服务器上没有"——这两句话在文档里也要分开写。

## 三、公开仓库的红线

这个仓库是**公开**的。服务器上能看到的东西,和能写进这里的东西,**不是同一个集合**。

下面这几类,一个字都不进仓库:

| 类别 | 说明 |
|---|---|
| 密码 | 尤其是 sudo 密码;任何形式、任何注释里都不行 |
| 密钥 / token / API key | 包括私钥文件头那一整段 |
| 管理与内网 IP | 服务器管理口、家里局域网、中转机、云主机,一律不写 |
| 内部端口 | SSH、RCON、AI 网关、地图内部端口、隧道入口 |
| 管理后台域名 | 只有孩子手里那几个公开地址可以写 |
| 玩家 UUID、玩家真实 IP | UUID 那种 8-4-4-4-12 的十六进制串也算 |
| 任何较长的十六进制串 | 宁可误伤,也不放过 |

**可以写的**,是本来就印在发给孩子的游戏内书里、或者 AI 村民会主动告诉孩子的那些:
游戏地址(`cn.laogaiphoto.com` / `mc.laogaiphoto.com`、基岩版端口 19132)、
地图网站 `map.v2good.com`、插件名和版本号、玩法规则、菜单结构、价格。

> **判据很简单:一个来路不明的人拿到这条信息,能不能多走一步?**
> 能进服务器玩 —— 可以写(孩子手里那本书上就有)。
> 能往管理面板、能往内网、能往钱和权限上多走一步 —— 不写。

### 这篇文档自己也受这条约束限制

**元文档在这里有个反直觉的地方:它不能把红线清单的字面值抄进来。**

推送前要跑的那个扫描器是**一张正则表**。如果这篇文档为了"讲清楚"而把那些正则
连同真实的 IP 段、端口号一条条抄下来,那这篇文档就变成了**那张表的第二份副本** ——
扫描器会命中它自己列出来的模式,而且这次命中的是一份**要推上去的文件**。

所以上面那张表是**用中文描述的**,一个字面值都没有。
这不是偷懒,是这类文档必须这么写。

## 四、扫描器必须有正对照(今天现场做的)

推送前跑一个 **9 条规则** 的扫描器:密码、三组 IP 段(管理机 / 内网 / 中转云主机)、
内部端口、管理后台域名、玩家 UUID、长十六进制串、常见密钥字段名。
任何一条命中,就不许推。

**但"扫描器没报警"和"没有密钥"是两回事。**
一个正则写错、或者 grep 的范围写错的扫描器,会稳定地、每一次都返回绿灯。
所以规矩是:**每次依赖它之前,先拿它扫一遍明知有密钥的目录,确认它真的会亮红灯。**

今天做了这个正对照:造一个目录,里面放一份**假的**配置文件,故意埋 6 样东西 ——
一个内网 IP、一个 SSH 端口、一个假 API key、一个管理后台域名、一个假玩家 UUID、一个 32 位十六进制串。
(**埋的具体值不能写在这篇文档里**,理由见 §三末。)

结果:

| 埋进去的 | 扫描器 | 说明 |
|---|---|---|
| 内网 IP | ✅ 命中 | |
| 管理后台域名 | ✅ 命中 | |
| 玩家 UUID | ✅ 命中 | |
| 32 位十六进制串 | ✅ 命中 | 同时触发"长十六进制"和"密钥字段"两条 |
| 假 API key 的字段名 | ✅ 命中 | |
| **内部端口** | 🔴 **漏了** | 见下 |

**漏掉的那一条为什么漏。** 端口那条规则要求**冒号紧贴数字**。
而我埋进去的写法是 `字段名: 端口号` —— 冒号后面有个空格。当场验了三种写法:

| 写法 | 会不会命中 |
|---|---|
| 冒号紧贴数字 | ✅ |
| **冒号 + 空格 + 数字**(YAML 里最常见的写法) | ❌ |
| **裸数字**(正文里说"端口是 XXXXX") | ❌ |

也就是说:这条规则**挡不住最可能发生的两种泄漏方式** ——
一份 YAML 配置片段,和一句大白话。
建议改成按整词匹配数字(不绑定冒号),代价是会误伤别的场合出现的同一串数字,
而在这件事上**误伤远比漏过便宜**。⚠️ 这个改动**我还没有做**,只是量出来了。

### 正对照顺带抓到的另外两个问题

**① 直接扫仓库目录,红灯必亮,而且和密钥无关。**
把扫描器指向仓库根目录,"长十六进制"那条必定命中 —— 命中的是 `.git/` 里的
**commit SHA(40 位十六进制)**,`.git/shallow`、`.git/logs/HEAD` 都是。

这是个**每次都会响的假阳性**,而每次都响的警报最后一定会被无视 —— 那时候它就彻底没用了。
改成只扫**被 git 跟踪的文件**(加上还没被跟踪的 `server/`)之后重跑 9 条:

```
hits=0   密码
hits=0   管理机 IP 段
hits=0   内网 IP 段
hits=0   中转 / 云主机 IP 段
hits=0   内部端口
hits=0   管理后台域名
hits=0   玩家 UUID
hits=0   长十六进制串
hits=0   密钥字段名
```

**9 条全 0。** 也就是说仓库的**内容**是干净的,红灯只来自 `.git` 内部 —— 但这个结论
是在换了扫描范围之后才拿到的,而不是扫描器原样告诉我的。

**② 扫描器会读到自己的规则表,并且为此自报一条红灯 —— 却不给证据行。**
它的"检测"那一步扫整个目录(包括自己),"打印命中行"那一步才把自己过滤掉。
于是当目录里只有扫描器自己命中某条规则时,输出是:**一行红色的规则名,底下什么都没有。**

今天扫素材目录就是这样:亮了三条红灯,逐条追下去发现其中两条(密码、内部端口)
命中的**只有扫描器自己那张正则表**,素材里一条都没有。

> **一个报警,如果你没法当场看到它命中了哪一行,你就没法处理它 ——
> 只能选择"相信"或者"无视",两个都不是工程。**
> 检测的范围和打印的范围必须是同一个范围。

### 那三条红灯里真实的那一条

素材目录里唯一真实的命中是**密钥字段名**,而且抓下来的素材里那几处的值
**已经在采集时就被换成了占位说明**,只留下了字段名。

> **顺序很重要:脱敏发生在"抓素材"那一步,不是"写文档"那一步。**
> 素材文件本身就不该带真值 —— 它虽然不进仓库,但它会进上下文、进日志、进别的会话。

## 五、今天现场吃到的一课:「配置加载成功」不等于「玩家看得见」

这一条和上面讲的是同一个毛病,只是换了场景,所以放在这篇里。

给资源世界加"第 6 次起收 1 金币"的时候,我的验证是:
改完配置 → 让插件重载 → **重载报告成功,配置解析没报错**。
于是我认为这件事做完了。

**实际线上发生的是:那一格按钮直接从菜单里消失了。**
原因是同一个格子上放了免费/付费两个按钮,而我漏写了决定"谁顶上来"的那个字段 ——
不写它不是"随便挑一个显示",是**整条链子塌掉,那一格变成空气**。
而空气在界面上长得和"这个功能被删了"一模一样。
孩子的反馈原话是"**传送按钮没了**",从上线到修好大约 **20 分钟**,期间谁都去不了资源世界。

把"我验了什么"和"用户会遇到什么"并排放,问题一眼就看出来了:

| 我验的 | 孩子真正会遇到的那一步 |
|---|---|
| 配置文件能解析 | —— |
| 插件重载返回成功 | —— |
| —— | **打开菜单,看那一格上有没有东西** |
| —— | **点它,能不能传送过去** |

我验的两条**全在服务端**,而出问题的那一步**全在客户端的那一格上**。
两边都真实、都通过了,只是**不相交**。

**同一天还有一条同形状的**:Owner 自己的账号是 OP,而 OP 不受次数限制、
剩余次数显示的是"无限"符号 —— 那个符号永远不等于 0,所以 **OP 永远只会看到免费按钮**。
拿 OP 账号点一百次,也测不到收费那条路。
要验收费,必须用一个**非 OP 的普通账号、把免费次数用完之后**再点。

> **能验的都验了,不等于验到了要紧的那一条。**
> **上线前先问一句:我这次验的,是不是用户真正会遇到的那一步?**

同一个形状在这个仓库里反复出现,已经被记成了单独的篇目 ——
[`docs/14`](../docs/14-the-gate-only-guards-half.md)(闸门只挡了一半)、
[`docs/10`](../docs/10-counting-deaths.md)(度量口径错了,结论全塌)、
[`docs/16`](../docs/16-bursty-sampling.md)(窗口太短,系统性低估)。
这次是第四次。写在这里,是希望下一次能在**上线之前**认出它。

## 六、`server/` 和 `docs/` 的分工

两个目录记的是**同一台服务器的两件事**,读者和用法都不一样:

| | `docs/NN-*.md` | `server/NN-*.md` |
|---|---|---|
| 写什么 | **踩坑教训** —— 一个具体的失败,怎么量出来的,真因是什么 | **功能说明** —— 这台服务器有什么、参数是多少、为什么这么配 |
| 主角 | 主要是 AI 玩家小麦(mineflayer 机器人) | 服务器本身:玩法、经济、领地、世界、登录方式 |
| 什么时候看 | 出了一样的症状,想知道别人是不是已经查过了 | 想知道"现在是怎么配的"、或者要改它 |
| 有没有结论 | 有,而且结论就是全文的目的 | 有,但主体是**事实表** |
| 时间性 | 一次事故的快照,写完基本不动 | **会过期** —— 服务器一改就要跟着改 |

另外两个文件:

| 文件 | 作用 |
|---|---|
| [`server/CHANGELOG.md`](CHANGELOG.md) | 按时间记**每一次改动**:改了什么、哪个文件、为什么、**怎么回滚** |
| 这一篇 | 元文档:上面这些是怎么写出来的、红线是什么 |

**两边互相链接,这是纪律不是装饰。** 已经这么做的地方:

- `server/04`(资源世界)在解释"最多试 24 次 vs 整体超时 30 秒"这一对数字时,
  直接链到 [`docs/13`](../docs/13-magic-numbers.md) —— 因为那是**同一个形状的坑**
  (内部等待必须小于外部封顶,否则内层逻辑是死代码)。
- 本篇 §五 链到 `docs/14` / `docs/10` / `docs/16`,理由同上。

> **规则:功能篇遇到一个"这个坑在 docs 里有"的地方,就链过去,不要重讲一遍。**
> 重讲会产生第二份会各自漂移的真相 —— 这个仓库已经吃过"同一个判据有两份实现"的亏。

### 写新篇目的时候

- 先抓素材,**再**写文档;不要凭印象补细节。
- 素材脱敏在采集那一步做。
- 每篇结尾必须有「⚠️ 这篇里我没核实的」,而且要**具体**("那 8 条命令我只确认了 3 条",
  不是"部分细节未核实")。
- 改动落 `CHANGELOG.md`,功能变化同步改对应的 `server/NN`。
- 推送前跑扫描器,**并且先用正对照确认扫描器是活的**。

## ⚠️ 这篇里我没核实的

1. **扫描器的端口规则我只量出了缺口,没有修。** 目前它挡不住"冒号+空格+数字"
   和"正文里的裸数字"两种写法(§四)。改法写在那一节,但**尚未实施**。
2. **扫描器"检测范围 ≠ 打印范围"这个问题也没修。** 我只确认了它会产生
   "红灯 + 零证据行"的输出,以及那两条红灯实际命中的是它自己的规则表。
3. **扫描器本身还不在这个仓库里。** 它现在是一个临时目录里的脚本 ——
   也就是说,**下一次会话找不到它**,而这正是这篇文档开头那句话要防的事。
   ⚠️ 建议把它连同正对照的用法一起提交进仓库(注意:提交进来之后,
   它那张正则表就成了仓库里的一份字面清单,要重新想清楚这样是否可接受)。
4. **9 条规则的"全 0"只覆盖了写这篇文档之前的仓库内容**,不包括这一篇自己,
   也不包括别的篇目后续的改动。推送前必须重跑一次全量。
5. **9 条规则够不够,我没有系统评估过。** 它是按"这台服务器已知的敏感面"列的,
   不是按通用的密钥格式(比如各家云厂商的 token 前缀)列的。
   一个真正的密钥扫描工具能命中的东西,它大概率命中不了。
6. **那 20 分钟事故的时长是按反馈和修复时间估的**,不是从日志里逐分钟核的。
   "谁都去不了资源世界"是按"那一格变成空气"推断的 —— 直接打命令的那条路
   (`/res go`)当时**很可能仍然可用**,我没有验证有没有孩子绕过菜单进去。
7. **`server/` 里其他篇目的素材可信度我没有逐篇复核。** 这篇讲的是纪律,
   不是审计结果 —— 每篇自己结尾那节「我没核实的」才是那一篇的真实底线。
8. **这套"改动必须落仓库"的规矩,目前靠自觉,没有任何机制强制。**
   没有 hook、没有检查、没有提醒。一次忘记写,就会多出一块像 `CHANGELOG.md`
   末尾那样的"日期未逐条复核"的化石。
