# 世界与跨服传送

> 这台服务器不是一个世界,是 **52 个**(3 + 49,推算过程见第一节):主世界 + 下界 + 末地,再加 **49 个随机资源世界**。
> 玩家去别处的主路径是**右键手里那把指南针**开菜单;命令也教了几条
> (玩法书里写了 `/menu` `/spawn`,老麦还教 `/res go`),但菜单是给孩子的正门。
>
> 这篇里有一个功能**目前多半是坏的**:菜单上那个「世界传送」按钮指向另一台服务器 Strix,
> 而 Strix 在 2026-09-16 复查时连不上(⚠️ 这一条来自另一次排查,**不在这篇的素材里** —— 见第五节)。
> 玩法书、AI 村民、菜单三处都还在教孩子用它。
> **这正是需要留档的那种断层 —— 说明还在,功能已经没了。**

## 一、一共有哪些世界

服务器上 `mv list`(Multiverse 的世界列表)第一页原文:

```
====[ Multiverse World List ]====
[Page 1 of 7]
world - NORMAL
world_nether - NETHER
world_the_end - THE_END
资源世界01 - NORMAL
资源世界02 - NORMAL
资源世界03 - NORMAL
资源世界04 - NORMAL
资源世界05 - NORMAL
```

| 世界 | 类型 | 干什么用的 | 玩家怎么去 |
|---|---|---|---|
| `world` | NORMAL | **主世界**。孩子的家、领地、出生广场都在这儿(资源世界不许圈地也不许设家 → 见第三节) | 默认就在这儿;`/spawn` 回出生点 |
| `world_nether` | NETHER | 原版下界 | 自己造传送门(**菜单里没有入口**) |
| `world_the_end` | THE_END | 原版末地 | 原版末地传送门(**菜单里没有入口**) |
| `资源世界01` … `资源世界49` | NORMAL | 随机荒野,挖矿砍树用 | 菜单「资源世界」或 `/res go` |

**证据链(这几个数字是怎么对上的):**

| 结论 | 出处 |
|---|---|
| 主世界目录名就叫 `world` | `server.properties`:`level-name=world` |
| 下界是开着的 | `server.properties`:`allow-nether=true` |
| 出生点没有保护圈 | `server.properties`:`spawn-protection=0` |
| 资源世界一共 **49** 个 | AI 村民老麦的 `facts` 原文「全服49个」;仓库 `CHANGELOG.md` 也记着「49 个资源世界全部上图」 |
| **总数 52,和分页对得上** | `mv list` 一页 8 条、共 **7 页**。3 + 49 = 52,`ceil(52 / 8) = 7` ✅ |

最后一行是这篇里唯一一个我自己算出来的校验:素材里只抓到了第 1 页,
但**页数本身能反推总数量级** —— 7 页装得下 49~56 个世界,52 落在里面。
如果哪天有人改了资源世界数量,`mv list` 的页数会先变。

> **52 个世界里只有 1 个是"真的":主世界。**
> 下界末地是原版附带的;49 个资源世界按"用完就换一片"来配
> (**"会被重置"是我从三条禁令反推的,素材里没有直接证据** → 见第三节末)。
> 需要长期保住的东西(领地、家)只能落在 `world` —— 因为资源世界既不许圈地也不许设家。

## 二、玩家的主入口:右键指南针

玩法书「✦ 去别的世界 ✦」那一段第一句就写着「右键**指南针**开菜单」
(更前面的「✦ 游玩说明 ✦」段给的是 `/menu`,两条路都通)。
主菜单(`DeluxeMenus`,`open_command: menu`、`register_command: true`、27 格;
文件名按 DeluxeMenus 的惯例写成 `menu.yml`,素材里只有菜单内容、没有文件路径 → 见文末)
里和"去别的地方"有关的三个格子:

| 格子 | 图标 | 显示名(三语) | 点下去做什么 |
|---|---|---|---|
| 13(正中) | `ENDER_PEARL` | 世界传送 / Travel / ワープ | 打开 `strix` 子菜单(去**另一台服务器**) |
| 20 | `DIAMOND_ORE` | 资源世界 / Mining / 資源 | 打开 `resworld` 子菜单(随机荒野) |
| 14 | `COMPASS` | 出生点 / Spawn / スポーン | `/spawn`,然后关菜单 |

菜单里**没有**任何指向下界和末地的按钮(抓到的主菜单一共 10 个格子,没有这一格)——
那两个世界只能按原版规则走传送门。
我的理解是这不算漏配:自己找地方开下界门本来就是原版玩法的一部分,
而资源世界和 Strix 是**不走路就到不了**的,才需要插件送人过去。
(⚠️ 素材里没有任何说明解释"为什么不放",这句是我的推测。)

「资源世界」那一格的 lore 里带两个占位符:

```yaml
- '&e今天还剩 &f%resworld_left%&e / %resworld_limit% 次'
```

也就是**次数是显示在按钮上的**,孩子不用去问"我今天还能去几次"。

> **能让玩家自己看见的状态,就别让他来问。**
> 剩余次数直接印在按钮上,是这个菜单做得最对的一处。

## 三、资源世界:49 片随机荒野

规则以**玩法书原文**为准(这是真正发到孩子手里的那份):

```
&2资源世界&0: 随机送你去
一片全新荒野,矿多树多
&c每天5次,不能圈地
&c不能设家,回不到上一个
```

| 规则 | 原文出处 | 为什么这么定(我的理解) |
|---|---|---|
| 每天 **5** 次 | 玩法书 + 老麦 `facts`「每人每天限5次」 | 资源世界是要**预生成地形**的,不限次等于让人随手刷 49 个世界的区块 |
| **不能圈地** | 玩法书 `&c不能圈地` | 圈地数据挂在世界上,而资源世界迟早要重置 —— 在这儿圈地就是圈了个会消失的地 |
| **不能设家** | 玩法书 `&c不能设家` | 同上。而且 `/home` 指到一个被重置的世界会很难收拾 |
| **回不到上一个** | 玩法书 `&c回不到上一个` | 每次随机挑一个世界,没有"上一次那片"的概念 |
| 主世界的家**完全不受影响** | 老麦 `quick-answers`原文「里面不能圈地,但你主世界的家一点都不受影响」 | 这句是专门写给孩子的安心话 —— 怕他们以为"传走了家就没了" |

命令入口是 `/res go`(老麦的 `facts` 和 `quick-answers` 都这么教),
菜单入口是 `resworld` 子菜单。

**两条素材之外、但同仓库有据的补充:**

- 插件叫 **ResWorld**,`daily-limit: 5`;
- 2026-09-17 加了一条:**第 6 次起每次 1 金币**,实现在菜单层(免费按钮和付费按钮占同一格,靠 `view_requirement` 二选一)。
  细节和那次线上事故(漏写 `priority` 导致按钮整个消失约 20 分钟)见同目录的 [`CHANGELOG.md`](CHANGELOG.md)。

**和资源世界有关的两个定时任务**(`systemctl list-timers` 原文):

| 定时器 | 时间(JST) |
|---|---|
| `mc-restart.timer` | 每天 **05:00** |
| `mc-chunky-resume.timer` | 每天 **05:10** |

⚠️ **下面整段是从定时器的名字猜的** —— 素材里只有 `list-timers` 的这两行,没有这两个单元的内容:
游戏服大概是每天凌晨 5 点重启,10 分钟后恢复 Chunky 的区块预生成;
也就是说 49 个世界的地形不是等人去了才现场生成,而是长期在后台一点一点铺出来的,
所以"重启后要把预生成接着跑"才需要一个专门的定时器。

> **打算随时换一片的世界,就得按"里面留不住东西"来配:不能圈地、不能设家、不保证回得去。**
> 反过来说,只要放开其中任何一样,这 49 个世界以后就很难再动了。
> (⚠️ 素材里**没有**"资源世界会被重置"的任何配置或说明 —— 这套因果是我从这三条禁令反推的,
> 真要重置之前请先自己确认一次。)

## 四、「世界传送」= 去另一台服务器

这一格不是去本服的另一个世界,而是**跨服**到一台叫 **Strix** 的服务器。

主菜单那一格的 lore 原文:

```yaml
display_name: '&b&l世界传送 &r&7Travel &r&8ワープ'
lore:
  - '&7去 &bStrix &7的世界逛逛'
  - '&7大厅 / 生存 / 空岛'
```

点进去是子菜单 `strix.yml`(`menu_title: 世界传送 / Travel / ワープ`,27 格):

| 格子 | 图标 | 目的地 | 点下去执行 |
|---|---|---|---|
| 11 | `BEACON` | **主大厅** Lobby ロビー(「Strix 的中心广场」「从那里还能去别的世界」) | `[close]` + `[player] kd go lobby` |
| 13 | `GRASS_BLOCK` | **生存世界** Survival サバイバル | (素材里这一项的命令被截断了,只抓到了 lore) |
| ? | ? | **空岛世界**(主菜单 lore 和老麦都提到它,但 `strix.yml` 的这一项没抓到) | ? |

### 🔴 最重要的一条:东西带不过去

`strix.yml` 里「生存世界」那一项的 lore,原文就把这件事写在按钮上:

```yaml
- '&e注意: 背包和金币不会带过去'
- '&e那边是独立的存档'
```

**Strix 是另一台服务器、另一份存档。** 按钮上明写了不带过去的是**背包和金币**;
既然是独立存档,等级、领地、家应该也一样不跟着走(**这几样按钮上没写、素材里也没写,我没验过**)。
把这句话印在**按钮**上(而不是只写在玩法书里)是对的 ——
孩子点按钮的时候不会去翻书,而"我的东西呢"是最容易闹起来的一类事。

### 回程:免密码登录

YangPortal(负责这套跨服的插件)配置里有一条,连注释一起:

```yaml
# 从 Strix 回来时凭签名通行证免密码登录
auto-login-on-return: true
```

**为什么需要这一条:** 本服是**离线模式**(`server.properties`:`online-mode=false`),
玩家靠服内的密码登录插件认证。如果不做这个,孩子从 Strix 回来就要再打一次密码 ——
一趟来回两次登录,体验上等于把这个功能废掉一半。
所以回程带一张**签名的通行证**,让它自动过认证。

目的地的名字映射(每一行的值都是配置原文,但**顺序是我按可读性拼在一起的**,
中间省掉了几项不进仓库的东西):

```yaml
destinations:
- lobby=主大厅
- survival1=生存世界
- survival2=空岛世界
cooldown-seconds: 5
check-interval-seconds: 20
```

`cooldown-seconds: 5` 读下来是"同一个人连续传送要隔 5 秒";
`check-interval-seconds: 20` 是每 20 秒做一次定期检查(检查什么,素材里没写)。

**这份配置里还有几项故意没写进这个公开仓库**:通行证的签名密钥、
跨服端口,以及一张"从哪个入口进来 → 去哪台机器"的路由表和默认回程主机。
留档的是**玩法**,不是能拿去连服务器的东西。
(玩家侧的公开地址只有两个,本来就印在玩法书上:中国大陆 `cn.laogaiphoto.com`、
日本/海外 `mc.laogaiphoto.com`,基岩版端口 `19132`。)

还有一处设计值得记:子菜单是 `register_command: false` ——
**它不注册自己的命令**,孩子没法直接打 `/strixmenu`,只能从主菜单点进来。
好处是入口唯一:哪天要把这个功能藏起来,只用改主菜单那一格。

> **跨服按钮必须在按钮上写清"东西带不过去"。**
> 玩家理解的"传送"默认是带着东西的;而跨服默认是不带的 —— 这两个默认值正好相反。

## 五、⚠️ 现状:这个按钮现在多半点了没用

**Strix 在 2026-09-16 的复查里连不上,而且它归另一位管理员维护。**

老实说清这条结论的来源:**它不在这篇的素材里**。
这批素材是从**羊羊这一侧**抓的配置(菜单、插件配置、玩法书),
配置文件只能告诉你"这个功能被配成了什么样",告诉不了你"对面还活着没"。
连通性是另一次排查的结论(2026-09-16),记在助手的笔记里。
所以这一条的状态是:**功能配置完好,对端未确认存活。**

而"还在教孩子用"这件事,是**素材里实打实有据**的 —— **4 个文件、6 处原文**:

| 还在教的地方 | 原文 |
|---|---|
| 主菜单 `menu.yml` | 「去 Strix 的世界逛逛 / 大厅 / 生存 / 空岛」 |
| 子菜单 `strix.yml` | 三个目的地按钮 |
| 玩法书 `Essentials/book.txt`(中文段) | 「&2世界传送&0: 去 Strix」「&0回家点&2回到羊羊世界」 |
| 玩法书(英文段) | 「&2Travel&0: go to Strix」「&0Back: &2Return to Yangyang」 |
| AI 村民老麦 `facts` | 「去别的服 → 菜单「世界传送」能去 Strix:主大厅、生存世界、空岛世界」 |
| AI 村民老麦 `quick-answers` | 「哈姆!菜单里点「世界传送」,能去 Strix 那边玩……空岛是从一座小岛白手起家,你的进度会自动保存,下次回来接着玩。」 |

老麦那条尤其要注意:它在配置里的字段名叫 `quick-answers`,
读下来就是**命中关键词就直接给出的固定答案**
(⚠️「不经过模型、也不查网络」这条来自插件的实现,**不在这批素材里** ——
素材里只有字段名和答案正文)。效果上是:只要有孩子问"怎么去别的服",
**它就会照着这段话回答**,哪怕对面已经连不上了。

**这是这篇最值得留档的一件事:**

> **说明比功能活得久。**
> 一个功能坏掉,它自己不会从菜单、从书里、从 NPC 的嘴里消失。
> 于是孩子按着说明去点,点了没反应 —— 而服务器日志里什么都不会报,
> 因为从我们这一侧看,"把人送过去"这个动作是成功发出的。

## 六、改这块的时候注意什么

| 要做的事 | 注意 |
|---|---|
| **摘掉 / 藏起 Strix 入口** | 至少要动 4 个文件:主菜单那一格、Strix 子菜单、`Essentials/book.txt`(中文段和英文段**确认写着** Strix,日文段素材里没看到 → 见文末;改的时候三段都翻一遍)、老麦的 `facts` + `quick-answers`。漏掉老麦 = NPC 继续教一个不存在的功能 |
| **改玩法书** | **已经发出去的书改不了** —— 书的内容在物品上,不在配置里。改完只能让孩子去菜单「玩法」**右键补领**一本(`kit guide`) |
| **改老麦的配置** | `McAI` 的配置文件开头写着「这个文件由后台「AI 村民」页面自动生成,手改会在下次保存时被覆盖」。手改 = 下次一保存就没了 |
| **改资源世界数量** | 别只改插件;`mv list` 的页数、BlueMap 的地图数、老麦嘴里的「全服49个」都会跟着不一致 |
| **动 `strix.yml` 的格子** | 同一格放多个 item **必须写 `priority`** —— 这条是 2026-09-17 在 `resworld.yml` 上用一次 20 分钟的线上故障换来的(见 [`CHANGELOG.md`](CHANGELOG.md)) |
| **改 BlueMap** | `render-thread-count` **必须 = 2**(素材里现值就是 2)。为什么不能往大调:见 [`CHANGELOG.md`](CHANGELOG.md) —— 调到 6 会把 CPU 抢光,玩家卡在「加载地形中」而 TPS 还显示 20.0 |

关于地图,一句就够(它有自己的篇):公开地址是 `map.v2good.com`,
老麦会主动告诉孩子;素材里抓到的**地图配置文件数是 55**,而世界是 52 —— 这两个数差 3,我没去查为什么。
