# 小麦 — 一个住在 Minecraft 服务器里的 AI 玩家

> **Field notes from running an LLM-driven [mineflayer](https://github.com/PrismarineJS/mineflayer) bot 24/7
> on a real, populated Minecraft server** — driven by a *small local model* (qwen3:8b), not a frontier API.
> Most of the value here is in [`docs/`](docs/): quantified failure modes, with the measurements that found them.
> Written in Chinese; the numbers and code are language-independent.

小麦(XiaoMai)是一个 **完全由 AI 操作、以真人玩家身份登录** 的 Minecraft 机器人。
它不是站桩 NPC —— 它自己走路、砍树、合成、打怪、安家、被怪打死、再爬起来。
每一步做什么由一个 **跑在家里局域网的小模型** 决定,不是云端大模型。

它住在一个**真实有人玩的服务器**上(一群小孩在同一个世界里盖房子),所以
"不破坏别人的东西" 是硬性红线,不是加分项。

## 这个仓库为什么值得看

不是因为代码写得好,是因为 **它跑了很久,而且每个结论后面都有实测数字**。

mineflayer 的文档告诉你 API 怎么调;这个仓库记录的是 **API 调对了、机器人还是不干活** 的那些情况。

几条有代表性的:

| 现象 | 看起来的原因 | 实测出来的真因 |
|---|---|---|
| 砍树成功率只有 **14%**(178 次尝试 25 次拿到木头) | 附近没树 / 树被判成建筑 | **背包 36 格全满**,`collectblock` 在挖之前就抛 `There are no defined chest locations!` —— 每一次都必然失败,和有没有树无关 |
| 合成"跑完了但背包里没多出东西" | 时序问题,等的时间不够 | 同一个原因:**背包满了,合成出来的东西没地方放** |
| 它老说"附近有树但砍不了" | 护栏太严 | 护栏没接到 `collectblock` **自己新建的那份 `Movements`** 上(它会顶掉你的) |
| 走两步就回来,`explore` 成功率只有 35% | 地形不通 / 被打断 | 走路目标写成 `GoalNear(x, **当前高度**, z)` —— 而 `GoalNear.isEnd` **算高度**。等于要求目的地的地面和脚下一样高,丘陵上**目标本身不可达**。换成 `GoalNearXZ` 后 62~100% |
| 死亡统计三个来源互相打架 | death 事件在重复触发 | **我的口径错了**:`grep logs/latest.log` 只抓到真实死亡的 **≈0%**。真相在 `world/stats/<uuid>.json`。而真正的死亡闭环是服务端插件配置 `respawn-at-home: true`:死 → 自动重生在家 → 怪就蹲在那儿 → 6 秒后再死 |
| 修了弓箭手(自杀式冲锋 1174 → 0 次)之后,**总死亡率反而升高** | —— | 修 A 打破了 B:新加的"自己造装备"链条抢占了"吃饭"的槽位,饿死从 0.8 → 2.7 次/小时 |

最后一条是这个项目最贵的一课:**局部修复会在别处制造新病灶,只看单项指标会骗自己。**

## 架构

> 🗺️ **一张图看懂:[小麦一家是怎么运转的](diagrams/xiaomai-family.md)**(思维导图 + 决策流程图,数据取自线上实际运行的配置)

现在是**三个 AI 玩家 + 一个 AI 村民**的一家人:小麦(丈夫)、麦娘(妻子)、麦豆(儿子),
加上住在出生点的爷爷**老麦**。三个 AI 玩家跑**同一份代码**,靠职业区分身份。

每个 AI 玩家的脑子分四层,优先级从高到低:

```
① 反射层    每秒一次 —— 掉血、落水、岩浆、窒息,当场处理,不问模型
② 紧急规则  快饿死就吃、没武器就做剑、天黑就睡、离家太远就传送回家
③ 脚本层    主力:大目标 → 小目标(脚本)→ 一步一步做
④ 兜底      一件活都开不了工时,才让模型挑一个动作
```

**模型只在「有好几件活可选」时才被问**,能开工的只有一件就直接干、一次模型都不调。
做没做完、能不能开工,都由代码判断。详见 [server/11](server/11-ai-player-brain.md)。

   │   硬规则 forced     ── "有木头没箱子 → 回家造箱子"(不问大脑)  │
   │   大脑决策          ── 从菜单里挑一个 + 参数                   │

   └───────────────────────────────────────────────────────────────┘
```

这个版本的问题:模型每 2.5 秒被问一次,很多时候根本没有选择可做,却要它"判断一个事实"
(比如「这件事做完了吗」)—— 实测它会一边说"已完成"一边回答"继续",白烧 364 秒。

</details>

**这几层的分工是这个项目最重要的设计决定:**

- **能力弱的模型不该决定生死。** 血量见底要不要逃跑、背包满了要不要腾格子,
  这些交给反射层,每秒判一次,不进菜单。
- **"必须先做 A 才能做 B" 靠叮嘱不管用。** 实测三次验证:在提示词里写
  "你要先安家再建造",小模型不会照做。只能靠 **菜单结构**(做不到的动作根本不出现)
  和 **硬规则**(直接夺权)。
- **模型负责"想做什么",代码负责"做得成不成"。** 例如玩家要东西时,
  给不给、给多少由模型按人格决定;而"背包里没有就给不出""不能超过持有量"
  "同一个人 3 分钟只能要一次" 由代码兜住。

  roles.js       角色机制:一份代码跑多个 AI 角色(父子/夫妻),各有人格和动作白名单
  roles.json     角色定义(人格文本可热更新,不用重启)

```

## 跑起来

```bash
npm install
cp .env.example .env    # 填你自己的服务器和模型地址
node src/bot.js
```

需要一个 Ollama 兼容的 `/api/chat` 端点。模型建议见
[`docs/03-local-small-model.md`](docs/03-local-small-model.md)——
**`qwen3` 系列必须显式传 `think: false`**,不传会返回空内容。

- [18 · 「这里没有超时」不等于「这里该加超时」](docs/18-no-timeout-is-not-a-bug.md) —— 砍树的中位耗时是 **14.1 秒**,而我准备给它加 **12 秒**超时。先量了一下,这个"补上缺口"会砍掉 **63%** 本来能成功的砍树
- [19 · 我调了停止,它没停](docs/19-stop-is-not-stopped.md) —— 停止信号有三种断法:**没人听**(任务里 5 个 await 只有 2 个听得见)、**被当正常情况吞掉**(库故意的,为了让它自己的取消能用)、**留下一个没人清的闩**毒死下一个动作。三种我们都踩到了
- [13 · 拍脑袋定的数字](docs/13-magic-numbers.md) —— 四个猜出来的常数各自制造了什么事故:内部等待 > 外部封顶让错误处理成了死代码、去重窗口比事件间隔还长吞掉 2/3 的真实事件、门槛和它衡量的动作不同量纲
- [20 · 地图不刷新,而地图一直在刷新](docs/20-the-map-was-not-slow.md) —— 「刷新很慢」的三层里,我只盯了最快的那层。服务器 5 秒就画好了,浏览器却被告知「这块图存 24 小时」。**CPU 满载不是瓶颈的证据**;以及:一条正确的旧教训,会变成下一次误诊的依据
- [21 · 把日志接到公开网页上,搬走的不只是你想要的那一行](docs/21-the-log-carries-more-than-chat.md) —— 想把游戏聊天显示到地图上,而同一个日志文件里当天躺着 **76 条明文密码**。判据必须是白名单:**漏一条的代价差了几个数量级**。外加两个不报错的 bug —— 它们坏掉的样子和「大家没在说话」一模一样
- [22 · 我只修了被报告的那一个](docs/22-i-only-fixed-the-one-that-was-reported.md) —— 一次「商店保存」抹掉了主菜单上两个手工加的按钮。我修好了被报告的那个,**还拿它去占了另一个的位置** —— 因为那一格空着,而它空着正是因为它也坏了。**没人报告 ≠ 没坏**;以及用对账(有文件没注册 / 菜单计数 23→24→25)代替听报告
- [23 · 「发出去了」不等于「收到了」](docs/23-sent-is-not-received.md) —— 手写的 RCON 客户端把包长度算成字符数,于是**每一条带中文的命令都被静默丢弃**:不抛错、不报错、回执是空串,而纯英文完全正常。我据此给 Owner 报过一个错结论。**我验的是它做到了,还是我做完了?**
- [24 · 装在别人家里的东西](docs/24-a-guest-in-someone-elses-house.md) —— 往 BlueMap 页面里加的输入框,**一打字就把地图开动了**(键盘归它);同一天后台保存报 permission denied(文件我用 root 建的)。**验权限必须用那个身份 —— 用 root 验权限,验的是 root**;以及测「没有发生」时必须配一个「应该发生」的对照组
- [25 · 一份代码,两个身份](docs/25-one-codebase-two-identities.md) —— 两个 AI 玩家跑同一份代码,而「有没有人在叫我」那个判据**写死了第一个的名字**。于是任何孩子说一句「小麦 跟我来」,**麦娘也会跟他走** —— 而那道「必须点名才算指令」的护栏就在几百行外,是同一个人写的。**失效方式是「多做了一件事」,在日志里和正常行为长得一样**
- [26 · 那不是对照组,那是两个不同的时刻](docs/26-that-was-not-a-control-group.md) —— 同一口箱子,小麦能开、麦娘开不了。这个「干净的对照」生出了**三个都能解释全部现象、但都是错的**解释(其中一个我写成了整篇 docs)。真相:两次观察隔了 **1 分钟**,而机器人正好在那 1 分钟里把土盖到了自己箱子头顶。**核实要核到「它发生过」,不只是「它可能发生」**
- [27 · 最吵的不是最贵的](docs/27-the-loudest-is-not-the-costliest.md) —— Owner 怀疑老麦「没人时还说话,浪费算力」。查下来老麦 164 句里 163 句是写死的台词,**几乎不耗算力**;真正在烧的是三个机器人各一个的**规划师**:每轮问一次模型,60 秒才用一次结果,其余扔掉 —— 而扔掉时不写日志,所以隐形。它是按「GPU 要一直忙」做的:**占用率是代理指标,它被优化到了满分,真正的目标丢了**
- [28 · 搜不到,不等于没说过](docs/28-not-found-is-not-never-said.md) —— 我对 Owner 说:另一个会话引的「你那两句话」我在记录里没搜到,可能是转述。其实两句都是 Owner 说的,错的是我的搜法:一种只看了「平时打的字」,漏了「AI 忙时插进来的字」;一种因为命令写法不对,根本没运行;还有一种,事后拿一句已知存在的话去试,只把搜索范围放宽一点,结果就从 169 行变成 0 行。我做过「能搜到」的对照,用的却是另一条命令。**说「没有」之前,先用同一条命令搜一句肯定有的话**

## 现状(诚实版)

**能做到的**:自己砍树、合成(木板→工作台→木棍→木剑)、自己摆工作台和箱子、
安家、存东西、打怪、躲弓箭手、饿了吃饭、卡住了自救、被点名才说话、
按人格决定给不给玩家东西、被打断的长任务能捡回来接着做。

**后来做到的**(这份 README 初版写的是"还做不到",一夜之后已经改观):
- 🏠 **它自己盖出了第一间房子** —— 4×4、墙高两格、门朝南,
  工作台/箱子/墙全是自己做、自己摆的(材料是泥土,还没有屋顶)
- ~~**死亡率**:打断 `respawn-at-home` 那个闭环之后,从爆发期的 228~336 次/小时降到 **7.4 次/小时**~~
  —— **这条已被我们自己推翻**:7.4 是一个短窗口的读数,换更大的窗口复测,爆发还在,
  59% 的死亡仍然发生在家门口([docs/16](docs/16-bursty-sampling.md))。终身均值是 **31 次/小时**
- 砍树成功率 14%(4.5 小时窗口)→ 一个 21 分钟窗口里最高 73%;后来稳定在 20~30%
  —— 两个端点的窗口差 13 倍,不该当成同一件事比

**仍然做不到 / 已知不好**:
- **不会种树**:它把家附近砍光了,背包里有几十个树苗,但动作清单里没有"种"
- **不会做盔甲**:服务器难度是 Hard,而它护甲槽经常是空的;有钻石,但合成白名单里没有装备
- ~~**不会用床、不会躲夜**:它有一张床,从不用~~ —— 2026-09-17 07:26 **它第一次睡着了**:
  天黑 + 附近有床就直接去睡(硬规则,不问模型)。床是村子里现成的,不是它做的。
  整个夜晚被跳过,重生点也跟着挪走了 —— 是好是坏还在观察
- **目标写死在配置里**:大目标是"存 64 块木头",实际已存 1,356 块,好几个小时前就完成了,
